# 活动排序与编辑 — 深度分析与实现方案

## 一、问题与根因（结论）

| 问题             | 根因                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------- |
| **AI 不看描述**  | 请求体与 prompt 只传 `name/role/category`，未传 `description`（及组织、时长等），模型无法评估深度与影响力。    |
| **活动修改不了** | 编辑弹窗内表单 state 仅在首次 mount 时从 `editingActivity` 初始化，打开编辑时未随 props 同步，显示空或旧数据。 |

---

## 二、资料与最佳实践

### 2.1 LLM 对课外活动的评价设计

- **评价维度**：Impact（影响力）、Leadership（领导力）、Uniqueness（独特性）、个人特质（坚持、共情等）。仅给「名称 + 角色 + 类别」无法判断 impact 与 depth。
- **做法**：Prompt 中应提供**有上下文的细节**（描述、时长、组织等），并明确要求模型基于这些证据给出评价与改进建议。
- **本系统**：System prompt 已写 “Depth + impact + consistency = green”，但 user prompt 未提供 depth/impact 的素材，需在活动部分加入描述（及可选组织、投入时长）。

参考：_Facilitating Holistic Evaluations with LLMs_（PromptLayer）、教育类 prompt 设计（persona + 结构化输出）。

### 2.2 长文本与 Token 控制

- 活动 `description` 在 DB 为 `@db.Text`，可能较长；多条活动直接全量塞入会占大量 token。
- **建议**：每条活动的描述做**按字符截断**（例如单条最多 280–350 字符，约 70–90 tokens），保证 10 条活动描述总量可控；截断处可加 “…” 标明省略。
- 可选：在 controller 或 ai.service 中统一写 `truncate(str, 300)`，便于后续按模型调整。

### 2.3 React 编辑弹窗与表单同步

- **现象**：用 `useState(initialFromProps)` 且弹窗常驻 DOM 时，props 变化不会重新执行 useState 初始化，导致“编辑时表单仍是上一项或空”。
- **做法**：用 **useEffect 在打开/编辑目标变化时，把 props 同步到表单 state**；依赖为 `[open, editingItem]` 或 `editingItem?.id`；仅在“弹窗打开”时写 state，避免关闭时覆盖用户未提交的输入。
- 参考：Stack Overflow “React Material UI Dialog form data state not set correctly when updated”、Ant Design “Form in Modal resetFields showing wrong data” — 一致建议用 `useEffect` + 数据依赖同步，或 `setFieldsValue` 式 API。

## 三、实现方案（细化）

### 3.1 AI 使用活动描述

**（1）扩展请求体与类型**

- **apps/api/src/modules/profile/profile.controller.ts**（约 107–112 行）
  - 构建 `request.activities` 时，每项增加：`description`（必传，可空字符串）、可选 `organization`、`hoursPerWeek`、`weeksPerYear`（便于模型判断投入度）。
- **apps/api/src/modules/ai/ai.service.ts**
  - `ProfileAnalysisRequest.activities` 项类型增加：`description?: string`，以及可选的 `organization?`, `hoursPerWeek?`, `weeksPerYear?`。

**（2）Prompt 中纳入描述并控制长度**

- **apps/api/src/modules/ai/ai.service.ts** 中 `buildDetailedProfilePrompt`（约 369–376 行）：
  - 对每条活动：先输出 `名称 - 角色 (类别)`；若存在 `description`，换行输出 `描述：` + 截断后的描述（建议单条 ≤300 字符，截断加 “…”）；若有 `organization` 或时长，可一行简短写出（如 “组织 / 每周 X 小时”）。
  - 中英文统一结构，例如：
    - 中文：`描述：${truncate(a.description, 300)}`
    - 英文：`Description: ${truncate(a.description, 300)}`

**（3）System prompt 微调（可选但推荐）**

- 在 “### 3. activities” 下增加一句：要求模型**依据活动描述与投入情况**判断深度与影响力，而不是仅看名称和角色。例如：
  - “Evaluate depth and impact using the activity descriptions and time commitment when provided.”

**（4）截断工具**

- 在 ai.service 或公共 util 中实现 `truncate(str: string | undefined, maxLen: number): string`，未定义或空返回 `''`，过长则 `str.slice(0, maxLen) + '…'`。

### 3.2 活动编辑表单同步

- **文件**：`apps/web/src/components/features/activity-form.tsx`
- **实现**：
  - 增加 `useEffect`，依赖 `[open, editingActivity]`（或 `open, editingActivity?.id`）。
  - 当 `open === true` 且 `editingActivity != null`：用 `editingActivity` 各字段调用 `setFormData({ name, category, role, organization, description, startDate, endDate, hoursPerWeek, weeksPerYear, isOngoing })`（日期格式化为 YYYY-MM-DD，数字转字符串）。
  - 当 `open === true` 且 `editingActivity == null`：调用与 `resetForm()` 相同的对象，清空表单（新增场景）。
  - 当 `open === false` 时不在 effect 里改 formData，避免关窗时误清空用户正在输入的内容。
- **验收**：点击某条活动的编辑，弹窗内展示该项完整信息；修改后保存，PUT 成功且列表更新。

### 3.3 奖项编辑表单（同类问题一并修复）

- **文件**：`apps/web/src/components/features/award-form.tsx`
- **问题**：与 ActivityForm 相同，`formData` 仅由 `useState(editingAward ? ...)` 初始化，无 props 同步。
- **实现**：同样增加 `useEffect([open, editingAward])`，在 `open === true` 时根据 `editingAward` 有无，分别 `setFormData(editingAward 各字段)` 或 `resetForm()`。
- 这样活动与奖项的“编辑改不了”体验一致修复。

## 四、实施顺序与验收

1. **活动编辑**：ActivityForm 增加 useEffect 同步 formData → 验证编辑后保存成功。
2. **奖项编辑**：AwardForm 同样增加 useEffect → 验证奖项编辑与新增互不串数据。
3. **AI 描述**：controller 传 description（及可选字段）→ ai.service 类型与 buildDetailedProfilePrompt 输出描述（含截断）→ 可选 system 提示句 → 验证分析结果能引用描述内容。

**验收要点**

- 编辑：活动/奖项在弹窗中正确回显，保存后列表与详情一致。
- AI：档案中若有带描述的活动，分析中的 activities 维度的 feedback/highlights/improvements 能体现具体描述或投入情况；无描述时行为与现网一致（仅名称/角色/类别）。

## 五、小结

| 项目        | 根因                         | 资料结论                                  | 方案要点                                                      |
| ----------- | ---------------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| AI 不看描述 | 未传 description，模型无依据 | 评价需 impact/depth，需在 prompt 中给证据 | 请求体 + prompt 带描述（截断），system 可强调“依据描述与投入” |
| 活动改不了  | 表单 state 未随编辑项同步    | 编辑弹窗应用 useEffect 同步 props → state | useEffect(open, editingActivity) 分支 setFormData / resetForm |
| 奖项改不了  | 同上                         | 同上                                      | AwardForm 同模式 useEffect(open, editingAward)                |
