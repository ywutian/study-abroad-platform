# 学校图片展示与管理员编辑 — 企业级方案

## 一、目标与范围

- **前台**：学校列表、学校详情页展示学校图片（logo）；无图时使用首字母占位，图片加载失败时降级为首字母。
- **后台**：管理员可查看、编辑每所学校的 Logo URL，支持预览与校验；关键操作可审计、更新后缓存失效。
- **数据来源**：**手动**（管理员编辑单校 Logo URL）+ **自动**（按学校官网域名通过 Logo.dev 批量/按需生成并写入或回填），两套均需完善落地。

---

## 二、现状摘要

| 项目              | 现状                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------- |
| 数据模型          | `School.logoUrl` 已存在（Prisma + DTO），API 已返回                                                                 |
| College Scorecard | 不提供 logo 字段，同步不写入 logoUrl                                                                                |
| Seed / 其他同步   | 未设置 logoUrl                                                                                                      |
| 管理员编辑        | 后端 PUT `/schools/:id` 支持 `logoUrl`（CreateSchoolDto/UpdateSchoolDto，含 `@IsUrl()`），但 Admin 学校页无编辑入口 |
| 缓存              | 仅 Scorecard 同步后调用 `invalidateSchoolCache`；管理员更新学校后未失效，可能看到旧数据                             |
| 审计              | 学校更新未写入 AuditLog                                                                                             |

## 四、管理员后台（企业级）

### 4.1 学校列表增强

- **文件**：`[apps/web/src/app/[locale]/(main)/admin/schools/page.tsx](apps/web/src/app/[locale]/(main)`/admin/schools/page.tsx)
- **接口**：请求 `/schools` 时后端已返回 `logoUrl`；前端 `School` 类型增加 `logoUrl?: string`（及 `website?: string`，供编辑表单使用）。
- **表格**：
  - 新增一列「Logo」：缩略图（约 32×32）或占位符（首字母/占位图）；无 logo 时显示「-」或占位。
  - 新增操作列「编辑」：每行一个按钮，打开「编辑学校」抽屉/对话框。

### 4.2 编辑学校抽屉/对话框

- **内容**：表单字段建议包含（与 `UpdateSchoolDto` 对齐）：
  - **Logo URL**（必显）：单行输入，占位符提示「https://...」；保存前前端校验 URL 格式；下方实时**预览**（小图，加载失败显示占位）。
  - 可选扩展：`name`、`nameZh`、`website`、`acceptanceRate`、`usNewsRank` 等常用字段，便于一次编辑多属性。
- **行为**：
  - 提交：`PUT /schools/:id`，body 仅包含用户修改过的字段（如 `{ logoUrl }` 或 `{ logoUrl, website }`）。
  - 成功：关闭弹窗、toast 成功、invalidates `['adminSchools', ...]` 与 `['school', id]`，列表与前台详情会看到最新数据（配合后端缓存失效）。
  - 错误：展示接口返回信息或通用「保存失败」。
- **权限**：仅管理员可访问；接口已受 `RolesGuard` + `Role.ADMIN` 保护。

### 4.3 校验与体验

- **前端**：Logo URL 输入框 blur/提交时校验格式（与后端 `@IsUrl()` 一致）；非法时禁用提交并提示。
- **预览**：输入变更时更新预览图；若请求失败（跨域或 404）在预览区显示「加载失败」或占位，不阻塞提交（后端仍可存 URL，前台展示时有 onError 降级）。

### 4.4 i18n

- 新增/复用 key：如 `admin.schools.logo`、`admin.schools.logoUrl`、`admin.schools.editSchool`、`admin.schools.logoPreview`、`admin.schools.logoUrlPlaceholder`、`admin.schools.save`、`admin.schools.saveSuccess` 等，中英文同步。

## 五、后端增强（企业级）

### 5.1 更新学校后缓存失效

- **文件**：`[apps/api/src/modules/school/school.controller.ts](apps/api/src/modules/school/school.controller.ts)` 的 `update` 方法。
- **改动**：在 `this.schoolService.update(id, data)` 成功后调用 `this.schoolService.invalidateSchoolCache(id)`，确保前台与 Admin 下次请求拿到最新数据（含 logoUrl）。

### 5.2 管理员操作审计

- **文件**：学校更新入口在 `school.controller.ts`（PUT），建议在该 controller 注入 `AuditLogService`（来自 `common/services/audit-log.service`）。
- **行为**：在 `update` 成功且当前用户为管理员时，调用 `auditLogService.log({ userId: currentUser.id, action: AuditAction.ADMIN_ACTION, resource: 'schools', resourceId: id, metadata: { updatedFields: Object.keys(data) } })`。
- **说明**：不记录完整 body（避免 PII/大对象），仅记录被更新字段名，满足「谁在何时改了学校哪些字段」的审计需求。

### 5.3 DTO 与校验

- **现状**：`CreateSchoolDto` / `UpdateSchoolDto` 已包含 `logoUrl` 且 `@IsOptional()` + `@IsUrl()`，无需改。
- **可选**：若希望限制仅允许 https 或白名单域名，可在 DTO 上增加自定义 validator 或管道。

## 六、图片数据来源：手动 + 自动双通道完善

### 6.1 手动维护（管理员单校编辑）

- **入口**：Admin 学校列表 → 每行「编辑」→ 编辑抽屉内 **Logo URL** 输入 + 预览。
- **流程**：管理员从官网/维基等复制图片链接，粘贴到 Logo URL，保存后 `PUT /schools/:id` 写入 `School.logoUrl`；后端校验 `@IsUrl()`，更新后缓存失效并写审计。
- **完善点**：见第四节（编辑抽屉校验、预览、i18n）；确保管理员可单独改 logo、也可与 name/website 等一起改。

### 6.2 自动按域名生成（Logo.dev 集成）

**目标**：对「有 website、无 logoUrl」的学校，用官网域名向 Logo.dev 取图并**写库**；同时支持管理员在编辑页**一键从域名生成**当前校的推荐 Logo URL（可改再保存）。

**6.2.1 环境与配置**

- 环境变量：`LOGO_DEV_TOKEN`（Logo.dev 的 publishable/secret key）；未配置时自动逻辑不执行、管理端隐藏「按域名填充」相关按钮。
- 配置校验：在 `env.validation.ts` 中不强制必填，仅当启用 Logo 自动功能时需配置；后端服务内若未配置则返回明确错误或跳过。

**6.2.2 后端：Logo 解析与写库**

- **域名解析**：从 `website` 提取 host（如 `https://www.stanford.edu` → `stanford.edu`），排除 localhost、空、明显非机构域名；可写工具函数 `extractDomainForLogo(website: string): string | null`。
- **Logo.dev URL 规则**：`https://img.logo.dev/{domain}?token={LOGO_DEV_TOKEN}`（可加 `&size=128` 等参数），得到的是图片 URL，可直接存为 `logoUrl`。
- **单校解析**：新增内部方法（如 `SchoolLogoService.getLogoUrlByDomain(website: string): Promise<string | null>`）：若未配置 token 返回 null；否则拼 URL，可选 HEAD/GET 检查可访问性，返回可用的图片 URL 或 null（失败/404 不写库）。
- **批量写库**：仅处理「有 website、当前无 logoUrl」的学校；逐条取域名 → 调 `getLogoUrlByDomain` → 若得到 URL 则 `prisma.school.update({ where: { id }, data: { logoUrl } })` 并 `invalidateSchoolCache(id)`；建议限流（如每校间隔 200–500ms）避免触发 Logo.dev 限频；记录成功/失败数，写 AuditLog（如 ADMIN_ACTION, resource: `schools`, metadata: `{ action: 'LOGO_FILL_BY_DOMAIN', success, failed, total }`）。

**6.2.3 后端 API 设计**

- **POST /schools/admin/fill-logos-by-domain**（Admin 专用）：
  - Body 可选：`{ limit?: number }`（默认 100，最大 500）。
  - 逻辑：查询有 website、logoUrl 为 null 的学校，按 limit 取一批，顺序执行「域名 → Logo URL → 写库 + 失效缓存」；返回 `{ filled: number, failed: number, skipped: number, message?: string }`。
  - 未配置 `LOGO_DEV_TOKEN` 时返回 503 或 400 并提示配置。
- **GET /schools/:id/logo-suggestion**（Admin 专用）：
  - 若该学校有 website 且当前无 logoUrl，用域名请求 Logo.dev 得到 URL，返回 `{ suggestedLogoUrl: string }`；失败或未配置返回 404/503。
  - 供编辑页「从域名生成」按钮使用，前端拿到建议 URL 后填入输入框，由用户确认再点保存。

**6.2.4 Admin 前端：自动能力入口**

- **学校列表 / 数据质量 Tab**：增加操作区「按域名填充 Logo」按钮；点击后弹确认（说明将对有 website 且无 logo 的学校批量请求 Logo.dev 并写库），确认后调用 `POST /schools/admin/fill-logos-by-domain`，展示进度或结果（成功/失败数量），并 invalidate 学校列表。
- **编辑学校抽屉**：在 Logo URL 输入框旁增加「从官网域名生成」按钮（仅当该学校有 `website` 且未填 logoUrl 时可用）；点击调用 `GET /schools/:id/logo-suggestion`，将返回的 `suggestedLogoUrl` 填入输入框并刷新预览，管理员可微调再保存（仍走 PUT 保存）。

**6.2.5 限流与降级**

- 批量任务：每校间隔 200–500ms；单次请求 limit 建议不超过 500，避免长时间占用。
- Logo.dev 失败（4xx/5xx、超时）：该学校跳过，不写入 logoUrl，计入 failed；不阻塞整批。
- 未配置 token：批量接口与 suggestion 接口均返回明确错误，前端隐藏或禁用「按域名填充」与「从官网域名生成」。

**6.2.6 审计**

- 批量填充：在触发 `POST /schools/admin/fill-logos-by-domain` 后写一条 AuditLog（ADMIN_ACTION, resource: `schools`, metadata: `{ action: 'LOGO_FILL_BY_DOMAIN', filled, failed, limit }`）。
- 单校「从域名生成」仅返回建议，不写库，由用户点保存走现有学校 update 审计即可。

### 6.3 手动与自动的协同

- 自动写库的 URL 与手动编辑的 URL 一致存于 `School.logoUrl`；管理员可随时在编辑中覆盖自动结果。
- 批量填充仅针对「无 logoUrl」的学校，不会覆盖已有手动或历史自动结果；若需「强制按域名重填」，可后续扩展为可选参数 `overwrite?: boolean`（本方案先不实现）。

## 七、实施顺序建议

1. **后端基础**：学校 `update` 后 `invalidateSchoolCache(id)`；学校 `update` 记录 AuditLog（ADMIN_ACTION, resource: schools, metadata 含 updatedFields）。
2. **前台 Web**：学校列表、详情展示 logo（img + onError 首字母）；类型补充 `logoUrl`。
3. **Admin 手动**：学校列表 Logo 列 + 编辑抽屉（Logo URL 输入 + 预览 + 校验 + 保存）；i18n。
4. **自动：后端**：`SchoolLogoService`（或挂到现有 School 模块）：域名解析、Logo.dev URL 拼接、单校/批量写库、限流；`POST /schools/admin/fill-logos-by-domain`、`GET /schools/:id/logo-suggestion`；环境变量 `LOGO_DEV_TOKEN` 及未配置时的降级。
5. **自动：Admin 前端**：列表/数据质量区「按域名填充 Logo」按钮 + 确认与结果展示；编辑抽屉「从官网域名生成」按钮 + 建议 URL 回填与预览；i18n。

## 八、验收要点

- **前台**：列表/详情有 logo 时显示图片，无图或加载失败时为首字母。
- **手动**：管理员可在学校列表看到 Logo 列，点击编辑可修改 Logo URL、看到预览，保存后列表与详情立即更新；AuditLog 有学校更新记录，缓存已失效。
- **自动**：配置 `LOGO_DEV_TOKEN` 后，管理员可点击「按域名填充 Logo」对无 logo 且有 website 的学校批量写库，结果有成功/失败统计并记审计；在编辑单校时可点击「从官网域名生成」得到建议 URL、填入并保存。
- **降级**：未配置 token 时，自动相关接口返回明确错误，管理端不展示或禁用自动按钮。
- 所有新增文案具备中英文。
