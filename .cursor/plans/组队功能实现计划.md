## 一、概述与目标

- **目标**：在现有「论坛内组队帖」之外，新增独立「组队」板块；队伍为 first-class 实体，支持同校申请、备考、时间线共享等场景。
- **范围**：后端新模块 Team（Prisma + API + 审计 + 单测）、前端 /teams 路由与导航、企业级认证/鉴权/错误码/审计/测试。
- **参考**：产品与用户流见设计报告；企业级缺口与补全建议见符合性分析；本计划给出可直接落地的后端/前端/检查清单。

## 二、后端实现（Backend）

### 2.1 Prisma Schema

**约定**：模型名 PascalCase；与论坛现有 `TeamMember`（ForumPost）区分，本模块成员表命名为 **TeamMembership**。

**Enums**

- `TeamVisibility`: PUBLIC, UNLISTED, PRIVATE
- `TeamJoinPolicy`: OPEN, INVITE_ONLY
- `TeamMemberRole`: OWNER, ADMIN, MEMBER
- `TeamInvitationStatus`: PENDING, ACCEPTED, EXPIRED

**Models**

- **Team**: id (cuid), creatorId, name, description?, schoolId?, tags (Json?), visibility, joinPolicy, maxMembers?, createdAt, updatedAt；关联 User, School, TeamMembership[], TeamInvitation[]；索引 creatorId, schoolId, visibility, createdAt。
- **TeamMembership**: id, teamId, userId, role, joinedAt；@@unique([teamId, userId])；onDelete Cascade；索引 teamId, userId。
- **TeamInvitation**: id, teamId, inviterId, inviteeId?, token? @unique, status, expiresAt, createdAt；索引 teamId, inviteeId, token, status。

**User / School**：在 User 增加 teamMemberships, teamInvitationsSent, teamInvitationsReceived；在 School 增加 teams。

（完整字段与 relation 定义见 [teams-backend-section.md](teams-backend-section.md) 第 1 节。）

### 2.2 API 表（Auth / 权限 / 审计 / 错误码）

| Method | Path                                    | Auth    | 权限规则                                                   | Audit              | 错误码                                      |
| ------ | --------------------------------------- | ------- | ---------------------------------------------------------- | ------------------ | ------------------------------------------- |
| GET    | /teams                                  | @Public | 仅返回 PUBLIC（或 UNLISTED 按需）；支持筛选                | No                 | BAD_REQUEST                                 |
| GET    | /teams/my                               | JWT     | 当前用户为成员的队伍                                       | No                 | —                                           |
| POST   | /teams                                  | JWT     | 创建者即 owner                                             | Yes: create        | BAD_REQUEST, CONFLICT                       |
| GET    | /teams/:id                              | @Public | PUBLIC/UNLISTED 可读；PRIVATE 仅成员；Service 返回 403/404 | No                 | NOT_FOUND, FORBIDDEN                        |
| PATCH  | /teams/:id                              | JWT     | OWNER 或 ADMIN                                             | Yes: update        | NOT_FOUND, FORBIDDEN, BAD_REQUEST           |
| POST   | /teams/:id/join                         | JWT     | OPEN 且未满、未已是成员                                    | No                 | NOT_FOUND, FORBIDDEN, CONFLICT              |
| POST   | /teams/:id/leave                        | JWT     | 成员；OWNER 须先转移或解散                                 | Yes: leave         | NOT_FOUND, FORBIDDEN, BAD_REQUEST           |
| POST   | /teams/:id/invite                       | JWT     | OWNER/ADMIN；未满、被邀请人未已是成员                      | Yes: invite        | NOT_FOUND, FORBIDDEN, CONFLICT, BAD_REQUEST |
| POST   | /teams/join 或 /teams/:id/accept-invite | JWT     | body 含 token/inviteId；校验后加入                         | Yes: accept_invite | BAD_REQUEST, NOT_FOUND, CONFLICT            |
| DELETE | /teams/:id                              | JWT     | 仅 OWNER（解散）                                           | Yes: disband       | NOT_FOUND, FORBIDDEN                        |
| GET    | /teams/:id/members                      | JWT     | 仅成员                                                     | No                 | NOT_FOUND, FORBIDDEN                        |
| DELETE | /teams/:id/members/:userId              | JWT     | OWNER/ADMIN 踢人；不可踢 OWNER                             | Yes: kick          | NOT_FOUND, FORBIDDEN, BAD_REQUEST           |

可选：INVITE_ONLY 的「申请加入」流程 — POST /teams/:id/apply、GET/POST applications（见 teams-backend-section.md 可选表）。

### 2.3 DTO 与校验（class-validator）

- **CreateTeamDto / UpdateTeamDto**：name 必填 @MinLength(1) @MaxLength(100)；description @IsOptional() @MaxLength(500)；visibility / joinPolicy @IsEnum；maxMembers @IsOptional() @IsInt() @Min(2) @Max(100)；schoolId @IsOptional() @IsUUID()；tags @IsOptional() @IsArray() @ArrayMaxSize(10)。
- **InviteDto**：inviteeId 或 email（按产品二选一），message @IsOptional() @MaxLength(200)。
- **JoinByTokenDto**：token @IsString() @IsNotEmpty()。
- **ApplyDto**（可选）：message @IsOptional() @MaxLength(200)。

### 2.4 审计（AuditLog）

- 扩展 `AuditAction`：TEAM_CREATE, TEAM_DISBAND, TEAM_INVITE, TEAM_LEAVE, TEAM_MEMBER_REMOVE, TEAM_TRANSFER_OWNER（及可选 TEAM_ACCEPT_INVITE）。
- 调用处：创建、解散、邀请成功、离开、踢人、转移 owner、接受邀请；`resource: 'teams'`，`resourceId: teamId`；metadata 仅非 PII 字段（如 action、可选 invitationId/targetUserId/newOwnerId）。

### 2.5 模块与测试

- **目录**：`apps/api/src/modules/team/`（team.module.ts, team.controller.ts, team.service.ts, dto/\*）。
- **依赖**：PrismaModule, AuditLogModule；在 AppModule 中注册 TeamModule。
- **单测**：team.service.spec.ts（create/join/leave/disband/invite/权限/审计调用）；team.controller.spec.ts（各端点调 service 传参正确、@Public vs JWT、CurrentUser）。Mock PrismaService、AuditLogService、CurrentUser。

## 三、前端实现（Frontend）

### 3.1 路由与 Middleware

- **不**将 `/teams` 加入 `PROTECTED_PATTERNS`，游客可访问 `/teams`、`/teams/[id]`（发现列表与详情）。
- **可选**：将 `/teams/create`、`/teams/[id]/settings` 加入 `PROTECTED_PATTERNS`，在边缘即要求登录；其余「我的队伍」、加入、申请由前端在点击时检查登录态 + API 返回 401 时跳转 login（callbackUrl 当前页）。

### 3.2 页面结构

- **teams/page.tsx**：PageContainer 7xl；PageHeader（title/描述/icon Users/color amber/actions =「创建队伍」）；Tabs「我的队伍」|「发现队伍」由 `?tab=my` / `?tab=discover` 驱动；发现 Tab 内筛选栏 + 卡片网格；我的 Tab 未登录时展示「登录后查看」或空状态。
- **teams/[id]/page.tsx**：返回按钮；Hero（名称、学校/标签、加入策略、人数、主 CTA）；下方描述、成员列表；owner 显示「设置」链到 settings。
- **teams/create/page.tsx**：单页表单（name 必填，其余可选）；成功跳转 `/teams/[id]`。
- **teams/[id]/settings/page.tsx**：编辑名称/可见性/加入策略；解散按钮 + AlertDialog 确认。
- **teams/join**：处理 `?token=...`，调接受邀请 API 后跳转 `/teams/[id]` 或展示错误页。

### 3.3 组件

- **TeamCard**：TouchCard/Card + 名称、学校/标签、人数、加入策略 Badge、查看/加入；设计系统 Badge、text-title、text-caption。
- **EmptyState**：custom 或 teams 预设；我的空、发现无结果、详情无成员三处文案。
- **Dialogs**：ApplyToTeamDialog、InviteMemberDialog、ConfirmLeaveDialog、ConfirmDisbandDialog；使用 AlertDialog/Dialog。

### 3.4 i18n（teams.\* 与 nav）

在 en.json / zh.json 中增加 nav.teams、nav.descriptions.teams 及 teams.\*（title、myTeams、discover、create、join、leave、invite、copyLink、settings、disband、memberCount、joinPolicy.open/inviteOnly、empty.my/discover/noResults/noMembers、errors.full/inviteExpired/forbidden/notFound/conflict、confirm.leave/disband 等）。完整键值表见 [teams-frontend-plan.md](teams-frontend-plan.md) 第 4 节。

### 3.5 数据与加载

- useQuery：['teams','discover', filters]、['teams','my']、['teams', id]。
- useMutation：create/join/leave/invite/disband/accept-invite；成功 toast + invalidateQueries；错误 toast 或 inline。
- 列表 Loading：与 TeamCard 布局一致的 Skeleton 网格；详情 LoadingState 或 Skeleton。

## 五、实施顺序建议

1. **Prisma**：在 schema 中增加上述 enums 与 Team / TeamMembership / TeamInvitation；生成迁移并执行。
2. **后端**：实现 TeamModule（Service + Controller + DTO）；实现 2.2 节 API；在 Service 内统一做可见性/角色校验并抛 ForbiddenException/NotFoundException；创建/解散/邀请/离开/踢人/接受邀请处调用 AuditLogService；扩展 AuditAction 并注册 TeamModule。
3. **后端单测**：team.service.spec.ts、team.controller.spec.ts；按检查清单逐项覆盖。
4. **前端**：新增 /teams、/teams/create、/teams/[id]、/teams/[id]/settings、/teams/join；middleware 按 3.1 决定是否保护 create/settings；导航增加「组队」（主导航 + More）；i18n 补全 teams.\* 与 nav。
5. **前端**：实现 TeamCard、列表双 Tab、详情页、创建页、设置页、邀请链接页；EmptyState 与各 Dialog；useQuery/useMutation 与 loading/error/toast。
6. **联调与验收**：按设计报告用户流与企业级检查清单做端到端验证；可选 Phase 2（Admin、限流、缓存）。
