# 组队功能 — 企业级实现检查清单

本文档为组队 (teams) 功能的企业级实现检查清单，供开发者在实现计划中逐项勾选。基于《组队功能企业级符合性分析》编写。

---

## 1. Auth matrix

| Endpoint                            | Public? | JWT required? | Permission                                                                                 |
| ----------------------------------- | ------- | ------------- | ------------------------------------------------------------------------------------------ |
| `GET /teams`                        | Yes     | No            | —（仅返回满足可见性的发现列表，如 PUBLIC）                                                 |
| `GET /teams/my`                     | No      | Yes           | Authenticated user                                                                         |
| `POST /teams`                       | No      | Yes           | Authenticated user                                                                         |
| `GET /teams/:id`                    | Yes     | No            | 按 visibility：非成员仅可见 PUBLIC 队伍精简字段；成员或 PRIVATE 需成员/登录由 Service 校验 |
| `PATCH /teams/:id`                  | No      | Yes           | Owner or admin only                                                                        |
| `POST /teams/:id/join`              | No      | Yes           | Authenticated user（OPEN 策略直接加入）                                                    |
| `POST /teams/:id/leave`             | No      | Yes           | Member only                                                                                |
| `POST /teams/:id/invite`            | No      | Yes           | Owner or admin only                                                                        |
| `POST /teams/:id/accept-invite`     | No      | Yes           | Authenticated user（body 含 token 或 inviteId）                                            |
| `DELETE /teams/:id`                 | No      | Yes           | Owner only                                                                                 |
| `GET /teams/:id/members`            | No      | Yes           | Member only（或 PUBLIC 队伍可对未登录隐藏；PRIVATE 仅成员）                                |
| `DELETE /teams/:id/members/:userId` | No      | Yes           | Owner or admin only（踢人）                                                                |

## 2. Audit events

| Operation      | When to log                                    | resource | resourceId | metadata fields (no PII)                                |
| -------------- | ---------------------------------------------- | -------- | ---------- | ------------------------------------------------------- |
| Create team    | After team + owner member created              | `teams`  | `teamId`   | `action: 'create'`                                      |
| Disband team   | Before/after team soft-delete or status change | `teams`  | `teamId`   | `action: 'disband'`                                     |
| Invite sent    | After invitation record created                | `teams`  | `teamId`   | `action: 'invite_sent'`, `invitationId`（可选）         |
| Leave team     | After member removed/left                      | `teams`  | `teamId`   | `action: 'leave'`, `userId`（当前用户，非 PII 若仅 id） |
| Kick member    | After member removed by owner/admin            | `teams`  | `teamId`   | `action: 'kick'`, `targetUserId`（可选，合规评估）      |
| Transfer owner | After owner role transferred                   | `teams`  | `teamId`   | `action: 'transfer_owner'`, `newOwnerUserId`（可选）    |

## 3. Error code to frontend

| error.code        | HTTP                        | Frontend handling                                                            |
| ----------------- | --------------------------- | ---------------------------------------------------------------------------- |
| `NOT_FOUND`       | 404                         | Show `teams.errors.notFound`, redirect or link to `/teams`                   |
| `FORBIDDEN`       | 403                         | Show `teams.errors.forbidden`, hide/disable action or redirect to `/teams`   |
| `CONFLICT`        | 409                         | Show `teams.errors.conflict` or specific key (e.g. already joined)           |
| `DUPLICATE_ENTRY` | 409                         | Show `teams.errors.duplicateEntry` (e.g. already in team / duplicate invite) |
| `BAD_REQUEST`     | 400                         | Show `teams.errors.badRequest` or validation message from `error.message`    |
| Team full         | `CONFLICT` or `BAD_REQUEST` | 400/409, message key e.g. `teams.errors.teamFull`                            |
| Invite expired    | `BAD_REQUEST` or `CONFLICT` | 400/409, message key e.g. `teams.errors.inviteExpired`                       |

## 4. Test checklist

### Backend

- [ ] **TeamService**: create team and creator is owner
- [ ] **TeamService**: join OPEN team
- [ ] **TeamService**: leave team
- [ ] **TeamService**: disband by owner
- [ ] **TeamService**: non-owner cannot PATCH/DELETE
- [ ] **TeamService**: non-member cannot see full detail for PRIVATE team
- [ ] **TeamService**: invite and accept
- [ ] **TeamService** (Audit): `AuditLogService.log` called with correct args for create / disband / invite
- [ ] **TeamController**: `GET /teams` returns 200 with list
- [ ] **TeamController**: `POST /teams` requires auth (401 without JWT)
- [ ] **TeamController**: `PATCH /teams/:id` returns 403 when not owner

### Frontend

- [ ] `/teams` accessible without login
- [ ] 创建队伍 redirects to login when guest
- [ ] List shows my / discover tabs
- [ ] Detail shows join / leave CTA by state

## 5. Optional / Phase 2

- **Admin**: `GET /admin/teams` (paginated, filters), `DELETE /admin/teams/:id` (force disband); audit with `ADMIN_ACTION`, `resource: 'teams'`, `resourceId`, `metadata: { action: 'admin_disband', reason?: string }`.
- **Per-user rate limit**: Stricter limits for `POST /teams` and `POST /teams/:id/invite` (e.g. 10/hour per user) via ThrottlerGuard or custom guard.
- **Redis cache**: Short TTL cache for `GET /teams` and `GET /teams/:id`; invalidate on create / update / disband / join / leave.
