# 活动「人为限定 + 权重」— 资料分析与方案建议

## 一、查阅结论概览

### 1. 业界常用的「活动分层」框架

- **4-Tier 体系**（College Vine、IvyD、多所顾问机构采用）按**成就层级/影响力范围**划分，而非按「活动名称」列清单：
  - **Tier 1**：国家级/国际级认可、罕见成就、或重要领导角色（如全国辩论冠军、国际青年乐团、创立有影响力的非营利组织）。
  - **Tier 2**：州级认可或高选拔性项目（如 All-State 乐团、州长学校）。
  - **Tier 3**：显著领导力或长期深度参与（如社团创始人、队长，且投入时间多）。
  - **Tier 4**：一般参与，无领导或突出区分度。

- **Common App** 提供的是约 **30 个标准化「类别」**（Academic, Art, Debate/Speech, Research, Work (Paid), Other 等），学生仍**自由填写活动名称与描述**；没有官方「预定义活动名单 + 权重」。

- 结论：**按「层级/影响力」赋权**与业界一致；若要做「有名活动人为给权重」，更稳妥的是做成**层级（tier）或声望权重**，而不是只认「名字是否在名单里」。

### 2. 招生官实际怎么看重活动

- **深度大于名气**：Holistic review 普遍更看重**持续投入与可证明的影响力**，而非单纯「听起来厉害」的活动名。一个在本地社团深耕多年、从普通成员做到负责人的经历，往往比一堆表面高大上但参与浅的活动更有说服力。
- **「未知」活动未必不重要**：若学生能把**描述**写清楚（角色、时长、成果、影响），招生官会据此判断；很多 Tier 2/3 活动在「名单」里并不出名，但描述好依然很有价值。
- 因此：**「我们不知道的活动多半就不重要」不宜做成硬规则**。更合理的是：**已知高声望活动给额外加分，未知活动仍用「深度/领导力/多样性」等既有维度计分，不额外惩罚**。

### 3. 与本项目现有设计对照

- **奖项**已采用「参考数据 + 权重」：`Competition` 表存已知竞赛，含 `tier`（1–5）；`Award` 可关联 `competitionId`，评分时用 tier 加权；未关联的奖用 level 等做 fallback。
- **活动**当前是：自由填写 name + category（枚举）+ role/description/时长等，评分用**数量、领导力关键词、总时长、类别多样性**，没有「已知活动名单」或 tier。

若要对活动做「人为限定 + 权重」，与奖项的**参考表 + 可选关联 + tier 加权**保持一致，是自然延伸。

## 二、方案方向对比

| 方向                                  | 做法                                                                                                                                                                                                      | 优点                                                          | 风险/缺点                                              |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------ |
| **A. 活动参考表（类似 Competition）** | 新建 ActivityTemplate：name、nameZh、category、tier(1–4)。用户添加活动时可选「从模板选」或「自定义」；选模板则关联 activityTemplateId，评分时对「已知」活动按 tier 加 prestige 分，未关联的仍用现有公式。 | 与 Award/Competition 一致；可维护、可扩展；支持中英文与别名。 | 需要维护模板列表与种子数据；用户要能选模板或留空。     |
| **B. 仅按名称匹配**                   | 维护一个「高声望活动名称/别名」列表，根据 activity.name 模糊匹配赋 tier，不改表结构。                                                                                                                     | 实现快、无 schema 变更。                                      | 易受拼写、中英文混用、同义表述影响；难以覆盖所有写法。 |
| **C. 仅层级（tier）字段，无名单**     | 活动表增加 tier（1–4），由用户或后台在编辑时选择。评分时用 tier 加权。                                                                                                                                    | 简单，不依赖名单。                                            | 用户可能乱选；没有「有名活动」的客观锚定。             |

**建议**：以 **A（活动参考表 + 可选关联）** 为主方案；若首期希望极简，可先做 **C**，再逐步引入 **A** 的模板与关联。

## 三、推荐设计要点（方案 A）

### 3.1 数据模型（思路）

- **ActivityTemplate**（参考表，类似 Competition）
  - 字段建议：id, name, nameZh, category(与现有 ActivityCategory 一致), tier(1–4), sortOrder, isActive。
- **Activity**
  - 增加可选外键 activityTemplateId 指向 ActivityTemplate。
  - 保留现有 name/category/role/description 等；若关联模板，name 可预填但允许用户改。

### 3.2 评分逻辑（与「未知=不重要」的平衡）

- **已知活动**（有 activityTemplateId）：在现有「数量 + 领导力 + 深度 + 多样性」基础上，按 **tier 加 prestige 分**（例如 tier1 加 N 分，tier2 加 M 分），总分仍 clamp 0–100。
- **未知活动**（未关联模板）：**仅用现有公式**，不再额外扣分；即「不知道的」仍按领导力、时长、多样性正常计分，只是没有「声望加成」。

### 3.3 产品与 AI

- **前端**：添加/编辑活动时，可先选「从常用活动选」（下拉或搜索 ActivityTemplate），选后带出 name/category，用户可补全 role/description/时长；仍保留「自定义」入口，不强制选模板。
- **AI 分析**：若采用「活动描述进 prompt」的改进，可同时在 system 或 user prompt 中说明：已知高 tier 活动会获得额外权重，但所有活动的描述与投入都会用于评估深度与匹配度。

### 3.4 种子数据

- 首期可录入一批「常见高声望活动」：如 USAMO、ISEF、Science Olympiad、RSI、TASP、全国/国际辩论与模联、All-State 类、知名夏校与科研项目等，并赋予 tier；其余逐步补充。

## 四、小结与实施顺序建议

- **是否要人为限定活动**：可以。做法上更推荐「**限定一批已知活动并给层级/权重**」，而不是限制用户只能填预定义项；未知活动仍可填，只是不享受「声望加成」。
- **「不知道的就多半不重要」**：适合体现为「已知的给加分，未知的不加分」，而不是「未知的扣分或计为 0」，以符合 holistic review 中深度与描述仍重要的实践。
- **实施顺序**：
  1. 确定采用 A（参考表）还是 C（仅 tier 字段）或折中（先 C 后 A）。
  2. 若 A：设计并迁移 ActivityTemplate + Activity.activityTemplateId；实现评分中 tier/prestige 加分与 fallback；再补前端「选模板」与种子数据。
  3. 与现有「活动描述进 AI」「编辑表单同步」等改进可并行，互不阻塞。
