> 基于「100% GCP」与「100% AWS」方案，按 MAU（月活用户）估算长期月费。  
> 价格以 us-central1 / us-east-1 为参考，实际以各厂商计算器为准。  
> 最后更新：2026-02

## 四、长期成本曲线（结论）

### 4.1 单用户月均成本（总月费 ÷ MAU，美元）

| MAU     | 100% GCP    | 100% AWS    | Vercel+Railway+Neon |
| ------- | ----------- | ----------- | ------------------- |
| 100     | 0.30–0.75   | 0.55–0.85   | 0.05–0.55           |
| 1,000   | 0.08–0.11   | 0.08–0.14   | 0.02–0.08           |
| 10,000  | 0.013–0.02  | 0.018–0.03  | 0.009–0.016         |
| 50,000  | 0.007–0.01  | 0.008–0.015 | 0.004–0.008         |
| 100,000 | 0.006–0.009 | 0.008–0.013 | 0.004–0.007         |
| 500,000 | 0.004–0.006 | 0.005–0.008 | 0.002–0.004         |

- **早期（100–1K MAU）**：当前栈（Vercel+Railway+Neon）通常最省；GCP 有免费额度时也可很低。
- **成长到规模（10K–100K MAU）**：GCP 与 AWS 单用户成本接近，都在约 **$0.005–0.02/MAU/月** 量级；当前栈随 Railway/Neon 按量会上去。
- **大规模（500K MAU）**：三套方案单用户成本都降到约 **$0.004–0.008/MAU/月**；GCP 略稳（Cloud Run 按请求）、AWS 上限高（若全 ECS 常驻）。

### 4.2 何时考虑从「当前栈」迁到「100% 单云」

| 情况                      | 建议                                                            |
| ------------------------- | --------------------------------------------------------------- |
| 月费持续 > $300–500       | 可算一笔账：迁到 GCP/AWS 的迁移成本 vs 未来 12 个月省下的费用。 |
| 需要统一合规/合同         | 倾向 100% GCP 或 100% AWS。                                     |
| 需要更细的 SLA / 多区     | 单云（GCP/AWS）更容易做多区与企业支持。                         |
| 长期在 1K–10K MAU、预算紧 | 可继续当前栈，把预算告警设在 $150–200/月。                      |

### 4.3 价格敏感时的选型

- **控成本优先、接受多厂商**：保持 Vercel + Railway + Neon，设好用量与预算告警。
- **要单云、且长期控成本**：**100% GCP** 在 10K–100K MAU 区间通常比 AWS 略低（Cloud Run 按请求 + 免费额度）。
- **要单云、且已有 AWS 或需最多区域**：**100% AWS**，API 用 App Runner 控制常驻成本，避免全 ECS 常驻。

## 五、Vercel / Railway / Neon 各档位能支撑多少用户

基于官方限额与计费方式，结合前文「单用户行为 + DB/存储随 MAU 增长」假设，给出各档位可支撑的 MAU 区间（均为约数，实际以你真实请求与数据量为准）。

### 5.1 Vercel：Hobby vs Pro

| 项目                       | Hobby                    | Pro                             |
| -------------------------- | ------------------------ | ------------------------------- |
| 月费                       | **$0**                   | **$20/月**                      |
| Fast Data Transfer（带宽） | **100 GB/月**            | **1 TB/月**                     |
| Serverless Invocations     | **100 万次/月**          | 100 万次内含，超出约 $0.60/百万 |
| 内含计算（Hobby）          | 4 CPU·时、360 GB·时 内存 | Pro 按需计费                    |
| 单次构建时长上限           | 45 分钟                  | 45 分钟                         |
| 并发构建                   | 1                        | 12                              |
| 商用/团队                  | 个人/非商用              | 商用、团队协作                  |

**与 MAU 的对应关系（Next.js 前端，PV 见前文）**：

- **带宽**：每 PV 若等效约 0.5–1 MB（HTML + 未缓存资源），100 GB ≈ **10 万–20 万** 等效 PV/月；结合「约 30–50 PV/MAU」→ **Hobby 100 GB 约可撑 2K–6K MAU**（视缓存与静态化程度）。Pro 1 TB 约 **20K–60K+ MAU**。
- **Invocations**：若约 20–40% 的 PV 走 SSR/API Routes，100 万次 ≈ **250 万–500 万** PV → 约 **5 万–15 万** MAU 量级才可能撞线；多数情况下**先碰到的是带宽**，不是 invocation。
- **构建**：Hobby 每日部署上限 100 次、并发 1，频繁发版会受限，与 MAU 无直接关系。

| 档位      | 可支撑 MAU（约，以前端带宽为主） | 说明                                   |
| --------- | -------------------------------- | -------------------------------------- |
| **Hobby** | **约 2K–8K MAU**                 | 100 GB 带宽是主要瓶颈；商用需 Pro      |
| **Pro**   | **约 20K–60K+ MAU**              | 1 TB 带宽；超出后约 $0.15/GB，可继续扩 |

**结论（Vercel）**：

- **Hobby**：适合 **约 2K–8K MAU** 的前端流量，$0；商用或需更多带宽/协作请用 Pro。
- **Pro**：可支撑 **约 20K–60K+ MAU**，月费 **$20** 起，超出带宽/ invocation 按量计费。

### 5.2 Railway：Hobby vs Pro

| 项目               | Hobby                                        | Pro                                      |
| ------------------ | -------------------------------------------- | ---------------------------------------- |
| 月费               | $5/月                                        | $20/月                                   |
| 内含用量           | **$5 资源抵扣**/月                           | **$20 资源抵扣**/月                      |
| 资源单价（超出后） | RAM $10/GB·月，vCPU $20/个·月，出口 $0.05/GB | 同左                                     |
| 单服务上限         | 6 副本，共 48 GB RAM、48 vCPU、5 GB 卷       | 42 副本，共 1 TB RAM、1000 vCPU、1 TB 卷 |

**计费逻辑**：订阅费固定；资源按实际用量计费，用量 ≤ 内含抵扣则只付订阅费，超出部分另计。

**与 MAU 的对应关系（NestJS API 单实例约 0.5 vCPU + 1 GB RAM 常驻时）**：

- 0.5 vCPU + 1 GB RAM 常驻 ≈ **$20/月** 资源费。
- Hobby：$5 抵扣后需再付约 **$15** → 合计约 **$20/月**，可支撑 **约 100–1K MAU**（请求量在 2.5万–25万 API/月 内）。
- Pro：$20 抵扣可覆盖同一配置 → 合计 **$20/月**，同样可支撑 **约 100–1K MAU**；若加 Redis 或略提配置，仍可在 $20 内做到 **约 1K–3K MAU**。
- 再往上（10K+ MAU）：需更高配置或多副本，资源费约 **$40–80/月**，Hobby 会变成 $5 + 超额，Pro 会吃掉 $20 抵扣后继续按量付；**计划上限**（48 vCPU/48 GB）在单服务内可撑到约 **几万 MAU**，但月费会明显上升。

| 档位      | 仅用内含抵扣时                       | 接受一定超额（约 $30–50/月）时          | 说明                    |
| --------- | ------------------------------------ | --------------------------------------- | ----------------------- |
| **Hobby** | **约 100–500 MAU**（极小实例或间歇） | **约 500–2K MAU**（0.5 vCPU 1 GB 常驻） | 超过 $5 用量即开始超额  |
| **Pro**   | **约 1K–5K MAU**（$20 抵扣内）       | **约 5K–15K MAU**（$50–80 总月费）      | 协作、更高副本/资源上限 |

**结论（Railway）**：

- **Hobby**：适合 **几百到约 2K MAU**，月费约 **$5–25**；再往上会超额，仍可跑但不如 Pro 划算。
- **Pro**：适合 **1K–15K MAU** 量级，月费约 **$20–80**；再往上靠单服务 48 vCPU/48 GB 仍能撑，但成本会接近或超过「迁到 Cloud Run + Cloud SQL」的区间。

### 5.3 Neon：Free / Launch / Scale

| 项目          | Free                                              | Launch                                        | Scale                    |
| ------------- | ------------------------------------------------- | --------------------------------------------- | ------------------------ |
| 月费          | $0                                                | 按用量（无最低）                              | 按用量（无最低）         |
| 存储/项目     | **0.5 GB**                                        | $0.35/GB·月                                   | $0.35/GB·月              |
| 计算          | **100 CU·时/项目/月**，单项目最大 2 CU (8 GB RAM) | $0.106/CU·时，最大 16 CU                      | $0.222/CU·时，最大 56 CU |
| Scale to zero | 支持（闲置约 5 分钟后缩零）                       | 支持（可关）                                  | 可配置                   |
| 典型参考      | 间歇/开发                                         | 约 $15/月（间歇 1 GB）；低负载 24/7 约 $20–25 | 高负载 100 GB 约 $700/月 |

**1 CU ≈ 1 vCPU + 4 GB RAM**；100 CU·时/月 若常驻 0.25 CU，约 100÷0.25÷24 ≈ **16.7 天** 就会用尽，故 Free 不适合 24/7 生产库。

**与 MAU 的对应关系（结合前文 DB 容量假设）**：

| MAU     | 约 DB 容量 | Free (0.5 GB, 100 CU·时)                 | Launch (按用量)                         | Scale (按用量) |
| ------- | ---------- | ---------------------------------------- | --------------------------------------- | -------------- |
| 100     | 0.1 GB     | 容量够，**计算紧**（常驻易超 100 CU·时） | 轻松                                    | 轻松           |
| 1,000   | 0.5 GB     | **存储到顶**，计算仅适合间歇             | 约 $5–15/月 可撑                        | -              |
| 10,000  | 3 GB       | ❌ 超存储                                | 约 $25–60/月（约 200–500 CU·时 + 3 GB） | -              |
| 50,000  | 12 GB      | ❌                                       | 约 $80–150/月                           | 可选           |
| 100,000 | 25 GB      | ❌                                       | 约 $150–300/月 或更高                   | 约 $400–700/月 |
| 500,000 | 100 GB     | ❌                                       | ❌ 建议上 Scale                         | 约 $700+/月    |

| 档位       | 可支撑 MAU（约）                                                 | 说明                                                          |
| ---------- | ---------------------------------------------------------------- | ------------------------------------------------------------- |
| **Free**   | **约 100–500 MAU**（且流量/查询偏少、能接受 scale-to-zero 冷启） | 0.5 GB 存满即约 1K 用户级数据；100 CU·时 仅适合间歇或极低请求 |
| **Launch** | **约 1K–30K MAU**（视是否 24/7、查询量）                         | 存储与 CU·时按量计费，约 $15–150/月 对应 1K–30K MAU           |

**结论（Neon）**：

- **Free**：仅适合 **内测/MVP、约 100–500 MAU**，且能接受数据库间歇休眠。
- **Launch**：可长期支撑 **1K–30K MAU**，月费约 **$15–150**。
- **Scale**：支撑 **30K–500K+ MAU**，月费约 **$200–700+**。

### 5.4 Vercel + Railway + Neon 组合：整体能支撑多少用户

以下为**整栈**（前端 Vercel + API Railway + 数据库 Neon）的保守支撑能力与月费；实际瓶颈可能是其中某一层（表中用「瓶颈」标出）。

| Vercel  | Railway | Neon   | 建议支撑 MAU（约） | 月费区间（约） | 常见瓶颈                          |
| ------- | ------- | ------ | ------------------ | -------------- | --------------------------------- |
| Hobby   | Hobby   | Free   | **约 100–500**     | $5–25          | Neon 存储 0.5 GB / 计算 100 CU·时 |
| Hobby   | Hobby   | Launch | **约 500–2K**      | $20–50         | Railway $5 抵扣用完后超额         |
| Hobby   | Pro     | Free   | **约 500–1K**      | $25–35         | Neon 存储/计算                    |
| Hobby   | Pro     | Launch | **约 2K–8K**       | $40–150        | **Vercel Hobby 100 GB 带宽**      |
| **Pro** | Pro     | Launch | **约 8K–15K**      | $75–170        | Railway 资源费                    |
| Pro     | Pro     | Scale  | **约 15K–50K+**    | $270–720+      | Railway 单服务上限或成本          |

说明：

- **Vercel Hobby**：带宽 100 GB/月，以前端 PV 估算约 **2K–8K MAU** 会触顶；再往上需 **Vercel Pro**（1 TB）或接受超额（约 $0.15/GB）。
- **Vercel Pro**：月费 $20，带宽与 invocation 足够支撑 **约 20K–60K+ MAU** 的前端；整栈瓶颈会先落在 **Railway 或 Neon**。
- 整体「Vercel + Railway + Neon」在 **约 2K–10K MAU** 区间性价比较好；超过 **约 15K–20K MAU** 可对比「100% GCP」的长期成本再决定是否迁移。
