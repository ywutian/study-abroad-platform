# 中国区支付订阅决策记录

- 决策日期：2026-07-19
- 状态：已确认
- 当前产品策略：全部产品功能开放，不限制积分，不向用户收费

## 当前决策

1. 支付订阅继续保持退役状态。
2. 所有生产环境必须使用：

   ```env
   PAYMENTS_ENABLED=false
   PAYMENT_PROVIDER=none
   ```

3. 不恢复旧的模拟支付流程，不使用 `User.role` 表示订阅或产品权益。
4. 历史 `Payment` 数据仅作为只读账本保留；后台退款和人工订阅调级保持禁用。

## 未来商业化渠道

| 场景                      | 推荐渠道              | 说明                                 |
| ------------------------- | --------------------- | ------------------------------------ |
| 中国大陆 Web              | 支付宝 + 微信支付     | 支付宝作为首批渠道，但不作为唯一渠道 |
| 海外 Web                  | Stripe/银行卡         | 与中国区渠道通过统一支付编排层接入   |
| 中国区 iOS App 内数字订阅 | Apple In-App Purchase | 不使用支付宝直接解锁 App 内数字功能  |
| Android App               | 对应分发商店 Billing  | 按实际分发商店政策实施               |

支付宝普通网站支付只代表单次收款能力，不应被视为已经支持自动续费。自动续费必须另行确认周期扣款/代扣产品准入，并实现用户授权、续费提醒、取消、失败重试、宽限期、异步通知、退款和对账。

## 目标架构

```text
中国 Web ── 支付宝 / 微信支付 ──┐
海外 Web ── Stripe ────────────┤
iOS ────── Apple IAP ──────────┼── 统一 Subscription / Entitlement 服务
Android ── 商店 Billing ───────┘
```

统一权益服务是所有客户端的唯一权限来源。支付渠道只报告交易和订阅状态，不能直接修改身份认证角色。

## 推荐实施顺序

### 第一阶段：单次购买闭环

1. 完成中国大陆企业商户主体和支付产品准入确认。
2. 优先接入支付宝 Web 月卡/年卡单次支付。
3. 建立独立的 `Subscription`、`Entitlement`、`PaymentAttempt`、`ProviderEvent`、`Refund` 数据模型。
4. 完成创建订单、支付回调验签、幂等处理、退款、每日对账和异常告警。
5. 由服务端统一授予和撤销权益。

### 第二阶段：渠道和生命周期扩展

1. 增加微信支付，避免中国区只依赖单一渠道。
2. 根据产品准入情况增加支付宝/微信周期扣款。
3. 实现续费、到期、宽限期、欠费、升级、降级和取消续费。
4. 增加 Apple IAP、App Store Server Notifications 和恢复购买。
5. 根据 Android 分发渠道增加对应 Billing 和服务端购买校验。

## 上线硬门槛

以下条件未全部满足时，不得把 `PAYMENTS_ENABLED` 改为 `true`：

- 已接入真实支付提供方，不存在模拟成功逻辑。
- 生产密钥存储、轮换和最小权限完成。
- Webhook 使用提供方要求的原始请求体验签。
- 提供方事件 ID 有数据库唯一约束并支持并发幂等。
- 支付状态、订阅状态和产品权益相互独立。
- 退款真实调用支付提供方，并通过异步结果确认。
- 已完成沙箱支付、重复回调、超时、失败、退款和对账测试。
- 已完成用户协议、自动续费说明、隐私政策、退款政策和发票流程审核。
- iOS 数字订阅符合 Apple IAP 和 App Store 中国区规则。
- 监控、告警、审计日志和人工对账工具可用。

## 明确禁止

- 禁止将 `VERIFIED`、`ADMIN` 等身份角色映射为付费套餐。
- 禁止仅修改数据库状态来表示已经退款。
- 禁止使用客户端支付成功结果直接发放权益。
- 禁止使用普通定时任务重复发起网站支付来模拟自动续费。
- 禁止在中国区 iOS App 内用支付宝直接解锁数字功能。
- 禁止在真实提供方尚未接入时恢复旧 `/subscriptions/subscribe` 模拟流程。
