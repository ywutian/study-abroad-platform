00 阅读指南与术语边界

避免把「开发时用的 Claude / Codex」和「用户打开的 Lumni AI」混为一谈。

三套「Agent」不要混用：
① 产品运行时 Agent — apps/api/src/modules/ai-agent/，用户聊天的 6 专家；
② 研发审查 Agent — .claude/agents/ 13 个，Step 0 相关性过滤，保证工程质量；
③ 数据闭环脚本 Agent — closure-agents/*.ts 等，调研结论固化为 TARGETS[] 写库，运行时不再调 Claude。
文档漂移注意：部分旧文档仍写「5 agents / 32 tools」或「~163 tools」。以源码为准： 6 agents / 45 LLM-visible tools（~163 是各 Tool Service 内部方法量级，非 OpenAI function schema 数）。

01 产品定位：做了什么

AI 驱动的智能留学申请辅助平台，把申请旅程产品化，并用确定性引擎出概率、用多 Agent 当顾问。

目标用户

  • DIY 申请者（学生 / 家长）— 主用户，中英双语
  • COUNSELOR — B2B 顾问工作台
  • OPERATOR — 学校 / CDS / 案例数据录入审核
  • ADMIN / SUPER_ADMIN — 运维、预测健康、AI 运维、Feature Flag

核心价值主张

  • 档案中心（类 Common App 结构化材料）
  • CDS 锚定、可解释的录取概率（非黑盒 AI 猜数）
  • 多专家 AI：文书 / 选校 / 档案 / 规划 / 简历
  • 社区：案例、论坛、大厅、组队、互评
  • 浏览器扩展：Common App 自动填表

四大产品支柱

Find Your College

搜索、筛选、对比、Reach/Target/Safety 清单、自定义加权排名。

Uncommon App

档案中心 + 选校清单 + AI 申请评估 / 活动优化。

Feature Hall

滑动发现、榜单、互评、招生官视角类体验。

Social

论坛、WebSocket 私信、Teams 竞赛招人滑动匹配、案例分享。

对外口径金句：AI 负责对话、工具调用、解释与写作辅助； 用户看到的录取概率数字由 Counselor 确定性引擎产出（CDS / AR 锚定 × 有界修正），LLM 不得发明评分引擎来「猜录取率」。艺术/音乐作品集校刻意 Tier 4 不给概率。

05 AI 三层模型（必读）

写 BP / 对外材料时必须分开三层，不可混谈「我们用了 Claude / GPT-5 Vision」。

Layer 1 — 研发/运营 AI（建设期）
  Claude Code · Codex · Cursor
  → 产出代码、规则、文档、closure 数据文件
  → ≠ 用户打开的 Lumni App

Layer 2 — 仓库内批量流水线
  pdftotext / pdf-parse / mammoth / cheerio
  → 文本 LLM → JSON（CDS 等）写入 PostgreSQL
  → 模型常见 gpt-4.1-mini / gpt-5.4-mini / gpt-4o-mini

Layer 3 — 线上产品（NestJS，终端用户）
  LLM_PROVIDER=openai · OPENAI_MODEL=gpt-4o-mini
  仅文本 Chat Completions（content: string）
  Embedding: text-embedding-3-small
  → /ai、文书、申请分析、预测解释
没有线上 Vision：请求体从不带 image_url；无 GeminiProvider；Anthropic 仅 env 枚举预留，生产只注册 OpenAIProvider。 截图上传只存储展示，不进模型。作品集校 = Tier 4 insufficient_data，刻意不做视觉评估。

07 六大专家 Agent 详解

配置：config/agents.config.ts · 类型：packages/shared/src/types/ai-agent.ts · AgentType enum。

ORCHESTRATOR · 留学助手
智能路由与任务协调；不亲自做文书/选校业务，委托专家。
gpt-4o-mini · temp 0.3 · maxTokens 2000 · 可委托全部 5 专家 · 工具 12

Prompt 主题：按意图 delegate；论坛/案例预测游戏/档案排名可直调；web_search 用于政策签证趋势；范围分 core / related（disclaimer）/ unrelated（礼貌拒绝）。

ESSAY · 文书专家
评估 · 润色 · 头脑风暴 · 大纲 · Prompt 检索。
temp 0.7 · max 4000 · 工具 7 · 委托回 Orchestrator

标准：真实性、细节、结构、自然声音、贴合题干。禁止代写全文。流程：get_profile → get_essays → search_essay_prompts → 可执行建议。

SCHOOL · 选校专家 enableReflection
搜校、对比、推荐、录取分析与预测解释。
temp 0.5 · max 4000 · 工具 14 · reflectionModel gpt-4o-mini

分层：Reach <30% / Match 30–70% / Safety >70%。推荐须附结构化学校 JSON 卡片。预测：优先 history/dashboard/list/trace；analyze_admission_chance 仅刷新。只解释公开字段，永不暴露 servedTrace / shadow / policy gate。

PROFILE · 档案分析师
多维档案审阅、优劣势、测评解读。
temp 0.5 · max 3000 · 工具 6

维度：学业、高中档、标化、活动、奖项、MBTI/Holland。输出可执行提升项。

TIMELINE · 规划顾问
ED/EA/ED2/RD、竞赛、考试、暑期、材料时间线。
temp 0.5 · max 3000 · 工具 7

缓冲：文书提前 2–3 月；标化 2 次机会；推荐信提前 1 月；提交留 1 周。优先级 🔴≤2w / 🟡2–8w / 🟢8w+。禁止空泛通用时间表。

RESUME · 简历专家
大学申请向简历（AO 阅读，非 ATS 求职简历）。
temp 0.4 · max 4000 · 工具 6

一页；顺序 Education→Awards→Activities→Service→Research→Work→Skills。权重：领导力 30% / 持续性 20% / 影响力 20% / 格式 15% / 匹配 15%。逐条 keep/condense/remove。

委托拓扑：专家之间不能互聊，只能 delegate_to_agent 回 ORCHESTRATOR；最大深度 AGENT_MAX_DELEGATION_DEPTH（默认 3）。 UI 可用 agentHint + context（prediction-results / selected-schools）偏置路由。

09 ReWOO 执行引擎（ADR-0003）

相对 ReAct「每工具一轮 LLM」，固定 2 次 LLM 调用（PLAN + SOLVE），只读工具可并行 — 文档称可减少约 67% LLM 调用。

PLAN · 调 LLM 一次规划全部 tool_calls→ EXECUTE · 不调 LLM · 并行只读 / 串行可变→ SOLVE · 流式综合答案（失败降级非流式）
维度ReAct本项目 ReWOO
LLM 次数O(N)2
延迟~5–15s~3–5s（量级）
并行无只读工具 Promise.all
职责拆分Runner 膨胀Runner 管上下文；Engine 管工作流

可观测 timing：planMs / executeMs / solveMs / totalMs。School Agent 另有 reflection 自我校验阶段。

11 记忆系统（三层 / 四层）

规范：docs/AI_AGENT_MEMORY_SYSTEM_SPEC.md · 11 个 memory services。

热层 Redis

会话缓冲，TTL 默认 86400s（MEMORY_CACHE_TTL）。Redis 宕机可降级内存。

冷层 PostgreSQL

事实/实体/消息持久化；多租户强制 userId。

语义层 pgvector

text-embedding-3-small 余弦召回。

工作层 / 归档

L1 WORKING（进程内）· L4 ARCHIVE（衰减后冷归档）。

Service职责
memory-manager统一编排入口
embedding · persistent-memory · redis-cache嵌入 / PG+向量 / Redis
memory-scorerScore = 0.4·Importance + 0.3·Freshness + 0.3·Confidence + AccessBonus≤0.1
memory-decayCron 03:00；decayRate 0.01/天；180d 归档 / 365d 删除
memory-compactionCron 04:00；相似度 0.92 去重合并摘要
memory-conflictKEEP_LATEST / HIGHEST / MERGE / ASK_USER…
summarizer · sanitizer · user-data摘要降本 · PII 脱敏 · GDPR 导出删除

Memory 类型（实现侧可能含 FACT / PREFERENCE / DECISION / SUMMARY / FEEDBACK 等）；Entity：SCHOOL / PERSON / EVENT / TOPIC。审计结论：75+ 查询带 userId，0 多租户泄露风险（2026-04-12）。

22 设计决策汇总与一句话结论

  1. ReWOO > ReAct — 控延迟与成本（ADR-0003）
  2. Counselor-primary 概率 — LLM 解释，不拥有 served odds
  3. 全局 LLMService — 域模块无环依赖
  4. 三级路由 — 便宜路径优先
  5. 纵深安全 — Guard → PromptGuard → Moderation → Audit + CI G1–G5
  6. 企业记忆 — Redis + PG + pgvector + 衰减/冲突/GDPR
  7. 结构化合同 — extractJsonFromLlm，禁止正则刮 JSON
  8. OpenAI 兼容单适配器 — Azure/DeepSeek 换 base URL
  9. 积分 + Token 双轨 + ThrottleAI
  10. SSE 断开感知 — 不空烧 token
  11. 无线上 Vision — 文本抽取 + 文本 LLM；作品集校拒绝假概率
  12. 研发 Agent ≠ 产品 Agent — 三层 AI 模型对外表述必分
一句话：Lumni 是生产级留学申请全链路平台（Web/Mobile/API/Extension）—— 用 Counselor 确定性引擎提供可校准、可审计的录取概率， 用 企业级多 Agent 编排（6 专家 · ReWOO · 45 Tools · 三层记忆 · 三层安全）提供对话、工具、写作与解释能力； 建设期另有 Claude/Codex 与 CDS 文本流水线，但不等于用户 App 内的模型服务。
