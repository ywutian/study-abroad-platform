# 业务任务选模实测：GPT-5.4 mini / 5.4 / 5.5 / 5.6

日期：2026-08-26（America/Los_Angeles）。范围：离线合成业务题，通过用户授权的现有 Relay 调用；不部署、不修改应用代码或生产配置、不执行业务工具。

## 结论

144/144 次测试完成，调用组合无重复。当前没有证据要求全面换成 5.6：5.4 在这组题、这个 Relay 和 30 秒截止内最稳定；5.6 Luna 值得作为轻量路由候选；mini 可以完成轻量题，但本批速度不如 Luna，单校长输出也不稳定。Sol 未显示必须引入的业务收益。

这不是“当前实现无需改进”的结论：应用默认分析超时短于本次观测耗时，另有输出事实依据、mini 别名和 token 上限口径问题。本文是模型选型筛查，不是录取命中率、生产发布或企业级质量验收证明。

## 测试方法

- 六个请求型号：`gpt-5.4-mini`、`gpt-5.4`、`gpt-5.5`、`gpt-5.6-luna`、`gpt-5.6-terra`、`gpt-5.6-sol`。
- 12 个独立场景，每型号每场景重复 2 次，共 144 次；两次重复不是 24 个独立业务场景。
- 相同输入和系统提示词、并发 2、每次截止 30 秒、请求输出上限 1,500 tokens。不传 temperature / reasoning effort，沿用当前 GPT-5 Provider 默认行为。
- 按场景和轮次轮转型号顺序。不重试、不 fallback，失败原样保留。
- 总报告 token 预算 1,200,000；每个执行片段限时 15 分钟。首片段完成 99 次后到时，第二片段只续跑剩余 45 次，不重跑或覆盖失败。
- 单校/组合分析复用当前项目的实际系统提示词；用户消息是冻结的合成 JSON，不是完整生产提示词包装。轻量题使用专门冻结的测试提示词。
- 复用项目 `streamRoutedOpenAI` / `collectRoutedOpenAI` 流式解析，包括模型标识、工具参数、usage 和 `[DONE]` 校验。未运行完整 ModelRouter、AgentRun、数据库、审批或业务工具执行链。
- 工具题只检验模型提出的调用；实际工具执行数为 0。因此不能把这些成绩当成服务端权限机制的安全证明。

评测遵循任务特定、固定准则、保留失败及复核评分偏差的原则；没有把长答案或新型号自动视为更好。[OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

## 评分复核与限制

原始自动分和复核分分别保留。以下规则对所有型号和轮次一致处理，不更改原始响应，不用重跑覆盖失败：

1. `nextActions: []` 在筛选题给定 Schema 中合法，不能仅因空数组判失败；不代表其建议质量优秀。
2. 未确认奖学金的学校被正确排除后，再列为待核实是有效行为。
3. 英文明确识别 binding conflict，不因中文关键词缺失误判为未识别；语言体验问题仍保留。
4. 明确声明 SAT 不能用于该校评估、只适用于其他学校，不因提到 SAT 而判为该校优势。

自动检查只覆盖部分 JSON 结构、字段/集合、工具选择、指定概率百分数及关键词，不是完整生产 Zod Schema 或全面事实核验；中文数字、语义隐含概率、证据与具体断言是否对应等存在盲区。

Codex 主代理另做了定性抽查，并非独立裁判或人工招生专家评审。抽查发现部分回答会在没有学校 GPA 对照数据时说“GPA 有竞争力/不是短板”，把 SAT 分布下沿近似为门槛，把假设的未来改善列入已有优势，或加入无来源的专业竞争判断。还存在内部字段名直出、重复 JSON key、语言不一致等问题。基础检查通过不能消除这些问题。

本批只有 12 个不同场景、2 次重复，单个 Relay 和一段时间窗口；未覆盖完整真实请求分布、不同地域/并发、长对话、真实数据库、不同 reasoning effort 或实际录取结果。不能据此宣称统计显著的整体能力胜负，也不能证明选校录取命中率提高。

## 接入与运行风险

- mini 请求别名返回 `gpt-5.4-mini-2026-03-17`；其余五个型号返回同名标识。本次仅在离线测试内显式绑定已探测标识，未放宽生产的精确型号校验。mini 在现有严格路由下还需要明确且经过测试的别名映射，不能仅改配置即视为接通。
- Relay 返回的型号是接口自报信息，不是独立验证其底层供应商或模型身份的证明。
- 当前代码默认单校 12 秒、组合 15 秒，而本筛查允许 30 秒。84/84 次分析尝试（包括失败尝试）耗时超过对应代码默认值。需检查测试耗时与业务 deadline 是否相容；未读取或更改线上覆盖配置，此处本地 Relay 耗时不能直接推导生产超时率。
- 9 次响应的 Relay 报告 completion tokens 超过请求的 1,500 上限（mini 4、5.5 1、Luna 1、Sol 3）。尚不能区分计量口径、参数转发或其他原因；不应仅依赖该请求参数作为可靠成本硬边界。
- 当前项目价格目录的 5.6 单价与本次查询的官方价格不同。本次不修改目录，接入前需要核对实际 Relay 账单和服务端预算估算。
