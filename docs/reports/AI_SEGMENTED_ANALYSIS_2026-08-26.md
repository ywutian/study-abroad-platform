# 分段分析与模型选择：工程验收结果

日期：2026-08-26。范围：本地代码、合成实际服务回放与回归；未提交、未部署、未改 `.env` 或真实凭据。

## 结论先行

采用 **GPT-5.4 主力、GPT-5.5 保留现有复杂任务**。分析和单条记忆抽取显式使用 `reasoningEffort=none`。本轮没有证据要求默认升级5.6；不放宽5.4 mini的Relay型号身份校验。

分段能力已经实现，但**不默认启用**。分段在成功样本中明显更快，却消耗更多输入token，并出现额外结构失败；按需求文档“完整成功率不下降”的门禁，应保留为可选候选，而不是因速度好看就发布。

默认策略：[ai-task-routing.recommended.json](../examples/ai-task-routing.recommended.json)。可选候选：[ai-task-routing.segmented-candidate.json](../examples/ai-task-routing.segmented-candidate.json)。使用与回退说明：[AI_MODEL_USAGE.md](../AI_MODEL_USAGE.md)。这些文件不会自行改变运行环境；路由总开关仍默认关闭。

## 实际做了什么

- 单校“现状判断→行动建议”、组合“风险判断→时间计划”两段，严格Schema、证据ID限制、禁止在分段叙述中重复百分比；原预测概率字段不变。
- 两段共享分组deadline和原24k/120秒运行预算；保留最多5校并发。输出合计学校1500、组合1000，且每段遵循原Router最少256输出token预留。
- `segmentationMaxSchools` 可按重点学校数量限制分段；未知数量默认不用分段。原未配置execution的分析继续使用旧12/15秒默认值，显式策略可以使用30秒deadline。
- 受控推理参数和模型能力声明冻结进原运行快照，旧快照哈希不因新字段而变化；不能经任意providerOptions覆盖。
- 分段保留各阶段型号、提示词哈希、耗时和usage。部分失败在显式分析策略下也显示degraded，不再把规则兜底混成完整AI成功。
- CoVE区分已核验、冲突、未知与不适用；缺字段、工具失败、模糊单位、否定/范围数值不算事实核验成功。该修复由原enableReflection控制，不是新建核验系统。

没有新Provider、Shell/文件工具、数据库迁移或权限扩大。原有Native Claude与路由工作区变更保留，不能把它们全部计为本轮新实现。

## 真实回放数据

本轮共 **342次真实Provider请求**：首轮178、条件分段96、记忆60、混合档位补测8。全部为合成输入；运行实际Profile→LLMService→ModelRouter→OpenAIProvider，以及实际Summarizer服务，无数据库、账号、业务工具或持久化记忆写入。

### 申请分析

首轮同一批12个场景变体，各重复2次，交替比较单段与全量分段。固定GPT-5.4、none、30秒分组deadline、24k运行预算；无模型重试或备用型号。条件候选为另批24次回放：仅单校分段，多校单段。

| 方案           | 完整成功 | 成功样本中位耗时 | 成功样本中位报告token |
| -------------- | -------: | ---------------: | --------------------: |
| 单段对照       |    22/24 |          38.08秒 |              10,417.5 |
| 全量分段       |    15/24 |          23.41秒 |                15,905 |
| 仅单校分段候选 |    21/24 |          22.91秒 |                15,955 |

不能把上表的耗时差直接当成全面性能提升：它只统计成功输出，各方案失败集合不同。

更可比的单校子集：单段16/16、全量分段15/16。对双方都成功的15组逐对计算，耗时下降比例的中位数为 **34.0%**，报告token增幅中位数为 **56.7%**。代价是额外一次结构失败，因此仍未达到默认替换门禁。

失败没有隐藏或重试刷分：

- 单段对照的两次失败均为5校大输入触发预算。
- 全量分段8次预算失败、1次Schema失败；三校/两校也会因重复输入无法完成组合分析。
- 条件候选2次5校预算失败、1次组合actionPlan错误嵌套unknowns。其24/24都保持概率字段和注入标记检查通过，失败可见；这只是限定检查下的受控结局，**不是24/24完整生成，也不是全面安全认证**。
- 首轮一个动作段含4条独立约束，被最初3条上限拒绝。第二轮将recourse.constraints上限明确改为4并加边界测试，保留首轮失败；没有事后改首轮分数。第二轮发现的错误字段层级仍被拒绝。

夹具审查也发现覆盖缺口：最初预测tier使用大写旧格式，mixed变体实际走了存储档位回退，不能算真正的混合档位验证。已修正为真实的`reach/match/safety`及相应不同概率，用最终默认策略补跑两次，**2/2完整通过、8次请求**，输出保留`REACH/TARGET/SAFETY`和原概率。此补测单独留证，不混入旧统计。三校都需要资助且资助未知，组合叙述仍会保守；自由文本和balance没有被宣称为稳定校准的专家结论。

### 实际记忆抽取

10类中英文消息×2次：明确事实、偏好、成绩纠正、一般提问、假设案例、引用注入、合成凭据、资助未知、专业决定等。使用实际extractFromMessage提示词，500输出token、15秒deadline，无存储操作。

| 型号 / 推理强度     | 严格规则通过 | 中位耗时 | P95耗时 |
| ------------------- | -----------: | -------: | ------: |
| GPT-5.4 / none      |        20/20 |  2.450秒 | 4.051秒 |
| GPT-5.6 Luna / none |        18/20 |  2.941秒 | 4.307秒 |
| GPT-5.6 Luna / low  |        17/20 |  3.518秒 | 4.917秒 |

Luna未通过的是保守的空输出规则：为明确虚构或一般问题保留了TOPIC/EVENT实体；实体描述仍标明虚构，**并非已发现伪造用户个人事实**。本产品当前不需要把这类讨论写入长期实体，因此不默认替换为Luna。该结果不代表Luna的通用能力排名。

最初150k报告token评测上限在56次后停止，后续只补齐4个未执行任务，完整保留前56次与原manifest；总60次、166,879报告tokens。没有重跑失败样本直到通过。

## 尚存边界

5校大输入在现有24k预算下仍可能降级。已完成“发现→阻止额外调用→保留可用结果→明确降级→留证”的工程闭环，但没有宣称修好了所有5校生成可用性问题。后续若要求5校始终完整生成，需要单独验证批处理或进一步压缩输入；本轮不通过调大预算掩盖问题。

未来升级5.6或默认开启分段，必须重新通过同输入完整成功率、事实边界、预算与成本门禁。当前运行环境仍未切换，由用户后续更新时启用选定配置。
