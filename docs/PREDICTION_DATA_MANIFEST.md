# 录取预测 —— 完整数据需求清单(全面补齐基线)

> 2026-05-22 · 这份文档是预测系统数据的**唯一权威清单**。目的:一次性确认「需要哪些数据」,然后全面补齐。
> 关联：[PREDICTION_ACCURACY_DECISION_2026-05-22.md](./PREDICTION_ACCURACY_DECISION_2026-05-22.md) · 2026-05-22 admissions-lens 历史决策记录（原始文档已归档移除）

数据分三个域,性质完全不同:

- **A · 校方参考数据** —— 每所学校的官方数据。可以**现在一次性补齐**(公开、官方、已知来源)。
- **B · 学生档案数据** —— 每个申请者的数据。不是「采集」,是「产品表单 + schema 要能完整接住」。可以**现在补齐**(schema/表单工程)。
- **C · 录取结果数据** —— 真实 admit/reject。**无法现在补齐**,只能随申请季积累(飞轮)。本轮明确不在范围。

### A 的关键缺口:CDS C7

C7 是每校官方发布的标准化表,把 **18 个录取因素**逐一评为 `Very Important / Important / Considered / Not Considered`:学业严苛度、班级排名、GPA、标化、文书、推荐信 / 面试、课外活动、才能、品格、一代、校友关系、地域、州籍、宗教、志愿、工作经历、demonstrated interest。

**它精确对应四轴**,是「这所学校官方说它怎么给每条轴赋权」—— 没有 C7,四轴的轴权重只能写死/均匀;有了 C7,四轴 lens 才真正 per-school、有权威。

### A 的补齐方式 —— 一次 CDS 抽取通关

**好消息:不是从零重抓。** closure 工程的 provenance 里**已存了 ~262 所学校的真实 CDS PDF URL**(如 Rice 的 `CDS_2024-25_WEBSITE.pdf`)。上表所有 ❌ 缺口(C7 + C2 waitlist + C9 提交率 + C10 排名 + C21/22 人数)**全在这同一批 PDF 里**。

→ **一个动作关掉 A 的全部缺口**:复用 closure-agents 管线,新增抽取目标,对已定位的 CDS PDF 做一次全节抽取。schema 侧加 1 个 JSON 列 `School.admissionFactors`(C7)+ 几个离散列(`pctSubmittingTests`、`classRankDistribution Json?`、`waitlistStats Json?`)。

## B · 学生档案数据(每个申请者)

引擎 `ProfileInput` 实际消费的字段 —— 这些不是「去外面采」,是「**产品表单要收 + schema 要干净接住**」。状态实测(/51 profile):

| 引擎需要的输入               | Profile schema 字段          | 现状                                                                                      | 缺口性质                 |
| ---------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------- | ------------------------ |
| GPA + scale                  | `gpa` `gpaScale`             | ⚠️ 20/51                                                                                  | 表单引导                 |
| 分年级 GPA                   | `gpa9/10/11/12` `gpaByGrade` | ❌ 0/51                                                                                   | **schema 有、表单没收**  |
| 标化成绩                     | `TestScore[]`                | ⚠️ 13/51 有                                                                               | 表单引导                 |
| 高中(及其 rigor)             | `highSchoolId` → HighSchool  | ❌ 0 链接                                                                                 | **表单没把高中关联起来** |
| 目标专业                     | `targetMajor`                | ⚠️                                                                                        | —                        |
| 国籍/国际生/州籍             | `nationality` 等             | ⚠️                                                                                        | 表单引导                 |
| **活动 + 档位 tier**         | `Activity[]`                 | ❌ **`Activity` 没有 `tier` 字段**;tier 只在 `ActivityTemplate`,36 条活动仅 10 条链了模板 | **schema bug**           |
| 奖项 + level/tier            | `Award[]`                    | ⚠️ 35 条/13 人                                                                            | —                        |
| hook(legacy/一代/体育生/URM) | `isLegacy` 等                | ⚠️                                                                                        | 表单引导                 |
| 文书                         | `Essay[]`                    | ❌ 6 条/5 人,`EssayAIResult` 0                                                            | 个人轴本就留白           |

### B 的关键缺口

1. **`Activity.tier` 是 schema bug** —— 学生自己的活动大半定不了档,课外轴连学生侧都站不稳。修法:`Activity` 加 `tier Int?`,活动录入时引导选模板/系统按类目兜底定档。
2. **分年级 GPA、高中关联** —— schema 字段在,但表单没收/没引导。预测时这些缺失 → 引擎降级 ×1.0。
3. 文书 —— 个人轴诚实留白,这一项不指望补。

### B 的补齐方式

不是数据采集,是**一次 schema + 档案表单审计**:`Activity` 加 `tier`;档案表单确保引导用户填 gpa-by-grade、关联高中、选活动模板。可现在做(工程)。

## C · 录取结果数据 —— 本轮明确不做

真实 admit/reject 结果(`PredictionResult.actualResult` 现 0 条)是唯一能**验证**预测准不准的数据。它无法被「补齐」—— 只能在申请季放榜后随用户上报积累(飞轮)。本轮不在范围;只需确保上报链路不被破坏(已有,见决策记录 Q2)。

补齐 A + B 后,预测系统的「输入侧」就**全面完整**了:每所学校有 C7 赋权 + 全套 CDS 录取数据,每个学生的档案能被引擎完整读取。剩下唯一的不确定是 C(结果验证)—— 那是飞轮的事,不是数据缺口。

## 边界 —— 补不齐的,永远补不齐

- **活动/文书/品格的「校方录取者分布」** —— 全世界不存在,学校从不公布。C7 的重要性评级是这两轴**唯一**的校方信号。不要试图补一个不存在的东西。
- **个体 holistic 录取的可预测性上限**(AUC ~0.6)—— 数据补齐能让「输入」完整,不能突破这个上限。补齐数据 ≠ 预测变神;它让预测**诚实地用满所有能用的信号**。

## 一句话

> 预测要的数据三个域:**A 校方参考**(一次 CDS 全节抽取补齐,C7 是骨架,PDF URL 已有)、**B 学生档案**(schema 修 `Activity.tier` + 表单审计补齐)、**C 录取结果**(只能等飞轮,本轮不做)。A + B 现在就能全面补齐,补完输入侧再无缺口。
