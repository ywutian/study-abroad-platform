# 录取预测「尽量精准」—— 决策记录

> 2026-05-22 · 6-lens architecture debate(统计严谨 / 产品务实 / 风险声誉 / 创始人 / 学生家长 / 留学顾问)+ Stage-4 devil's advocate
> 关联：2026-05-21 历史回测记录（原始文档已归档移除） · [PREDICTION_ACCURACY_STRATEGY.md](./PREDICTION_ACCURACY_STRATEGY.md)
> 触发:tier-first 改版(PR #268)已上线后,平台所有者要求「让大概的范围也尽量精准」。

## 背景事实(已验证)

- 个体 holistic 录取预测天花板低(论文 AUC ≈ 0.6);**校准**才是诚实指标,非点命中率。
- 数据库实测:404 校(241 有完整 CDS/录取率);`AdmissionCase` 2454 条、1136「可用」,但 `gpa11/12`、结构化 `testScores`/`activities`、`nationality` **100% 空**,`tags` 模板化,大量是 AI 灌入的合成种子数据。
- **`PredictionResult`(91 行)+ `PredictionSnapshot`(408 行)两张表已存在且在写**,`actualResult`/`outcomeLabel` join 目标字段已在 schema 里、全空。真实录取结果反馈 = 0 条。
- 51 个用户 profile,平台基本 pre-launch。
- 现状缺陷:概率区间写死 ±5pp;`confidence` 硬编码 `'medium'`。

## Contested questions

1. pre-launch、51 用户、0 真实结果的平台,现在投入做预测校准基础设施(修数据入库 / 结果飞轮 / Platt 校准)是否过早?
2. 结果回收飞轮冷启动要 1-2 年 —— 现在该建「记录」/「问卷」还是都不建?
3. 点概率多年内不可验证 —— 该不该彻底放弃概率数字/区间,只给档位?还是保留诚实区间?
4. 合成的 `AdmissionCase` 种子数据怎么办 —— 修入库 / 清掉 / 保留标注?
5. 规则引擎硬编码修正系数不可验证 —— 继续改 / 冻结 / 替代?

## Unanimous / 一致点 — adopt directly

- **Q1 → 只做最小;Phase 5(Platt 校准)现在不立项。** Why:0 条真实结果时校准是 calibration theater,Platt scaling 在 n<200 时斜率本身置信区间能跨过 1。
- **Q3 → Phase 1「诚实输出」必做、立刻做。** Why:零新数据依赖、纯算法、今天能交付;写死的 ±5pp 和硬编码 `'medium'` 是「把『我们不知道』伪装成『我们精确知道误差是 5%』」—— 比没有区间更糟。
- **Q4 → 修入库管线不做。** Why:补 100% 空的结构化字段「补出来的还是编的」,给假数据化妆,ROI 极差。

## Majority / 多数点 — adopt with noted dissent

- **Q3 → 废除精确点概率数字;保留「诚实区间」,但区间退居二线、档位是头条。** Why:档位对个体 holistic 的不可约方差稳健,区间表达「中心 + 不确定宽度」,点概率两者都做不到。
  Dissent(风险视角):即便诚实派生的区间,在用户端仍会被当成承诺;若日后出现因区间引发的纠纷,应重新考虑退回纯档位。

## Conflicts → resolution / 分歧 → 裁决

### Q2 — 飞轮:建什么?

- Positions:Stage 2/3 六方一致「现在建 `prediction_snapshot` 快照表(2-3 人日),推迟问卷」;Stage 4 devil's advocate:「别建 —— 规则引擎确定性 + 已存 profile = 快照可重算,且今天设计的 schema 到能校准时已过时,pre-launch 的几百行预测是 QA 噪声」。
- **Resolution:不新建任何快照表。** devil's advocate「别建」对了,但它「重跑确定性引擎即可重算」的理由是错的 —— 服务出去的预测依赖**可变、未版本化的学校 CDS 数据 + 可变的 profile**,无法事后重算。真正的答案两者都没说全:**快照基础设施已经存在**(`PredictionResult` + `PredictionSnapshot` 两张表在写,`actualResult` join 字段已在 schema)。所以正确动作不是「建 2-3 人日的新表」,而是**一次核查**:确认 `PredictionResult` 落库的是 serve-time 的 tier/区间/引擎版本/anchor 且不被覆盖。问卷 UI 推迟到首批用户进入放榜期前 1 个月。**Q2 净工程量 ≈ 0** —— 是一次验证,不是一次建设。
- Counter-argument considered:「irreversible asset,漏存一天少一天 ground truth」—— 被否决,因为(a) pre-launch 服务的预测几乎全是测试数据,(b) 真正的 join 目标 `actualResult` 字段已存在,(c) 表已经在写。

### Q5 — 规则引擎修正系数:继续改 vs 冻结?

- Positions:5 方「冻结」(改不可验证的标量 = 拿直觉换直觉、出事说不清);留学顾问「继续改」(冻结 = 退化成 CDS 计算器,丢掉 ED 加成/国际生 aid 硬伤/专业竞争度这些上千案例验证的领域知识,抓不到「冲稳保失衡」)。
- **Resolution:分两层。系数的数值层冻结(标 `v-frozen` + 审计日志);分类逻辑层 + 缺失因素清单持续迭代。** 留学顾问从 1-vs-5 移动到此 —— 因为统计严谨指出「领域知识应编码为**结构/维度**,不是未观测系数的点估计」;`edBoost = 0.12` 是猜,把 ED 作为分组维度让它日后可被数据移动才是用证据。学生独立贡献了关键拆解:抓「冲稳保失衡」只需要**档位分布**,根本不需要可验证的概率系数 —— 所以**新增一个独立、可自由迭代的「选校结构诊断层」**(检测「你 8 所里 7 所是冲刺档」)。
- Counter-argument considered:「冻结 = 退化成计算器」—— 被否决,因为冻结的只是标量数值,不是冻结维度;结构判断照常活着。
- 例外(留学顾问的保留意见,已采纳进决策):事实性错误(如国际生拿不到 need-based aid 却被算了高概率)按 **bug** 修,不受冻结约束 —— 事实错误 ≠ 系数微调。

## Sharpened points / 锐化的点

1. **Q5:从「改 vs 冻结」二选一 → 三层拆解。** 草案是「冻结还是继续改」;辩论锐化为「**数值层冻结 / 分类逻辑层迭代 / 新增选校结构诊断层**」。配套纪律(留学顾问):任何系数改动必须绑定一条**可证伪的领域断言 + 来源**,只允许 4 档量级(无/弱/中/强),禁止小数点微调。这是本次辩论最大的智识产出。
2. **Q3:从「砍掉数字」→「保留区间但约束其形态」。** 风险视角从「连区间一起砍」移动到:保留诚实区间,但施加**形式约束** ——(a) 区间与档位卡同屏不可分离渲染、不作为可独立截图/分享的 DOM 单元;(b) 强制结构化「非承诺声明」字段(`basisLabel`:「基于历史 CDS 分布 / N 个相似案例,非个人录取承诺,未经实证校准」),与区间同级返回、不是脚注;(c) 零校准期区间宽度有**下限**,禁止输出伪精确的窄区间;(d) 任何冲刺/匹配档位卡强制并列「你的清单需要 N 所保底校」提示。
3. **Q2:从「现在建快照表」→「什么都不建」。** devil's advocate + 数据盘点联合得出:快照表已存在,新建是冗余。
4. **Q4:从「标注即可保留」→「物理隔离;在叫『真实』的面板里,标注不构成补救」。** 创始人从「示例标够用」移动到此 —— 面板名「相似**真实**案例」本身就是和用户签的合同,往里塞合成对象是「用合同字眼骗人」。

## Minority report / 少数派记录

**风险/法律视角(Q3)**:即使施加了全部形式约束,一个诚实派生的区间在用户端仍是「承诺」—— 「诚实」描述生产过程,「承诺」描述接收效果,两者是范畴不同的属性。截图传播时留下的永远是数字、不是免责脚注。**若产品上线后出现任何因区间引发的家长纠纷/舆情,本决策应被重新打开,认真考虑退回「纯档位 + 规则拆解、完全不出现数字区间」。** 这条是本记录里日后最该回看的一行。

## Build sequence / 落地顺序

**现在做(本批):**

1. **Phase 1 · 诚实输出(1 PR)** —— `confidence` 从真实信号(anchor tier、缺失字段数、per-school 案例数)派生,杀掉硬编码 `'medium'`;概率区间改 log-odds 空间计算、宽度随 confidence 缩放、设宽度下限;替换写死的 ±5pp。
2. **Q4 · 合成数据隔离(1 PR)** —— `AdmissionCase` 加 `dataProvenance` 字段(`SYNTHETIC_SEED` / `USER_REPORTED` / `VERIFIED`);「相似真实案例」面板与 `/cases/similar` 端点**只返回非 SYNTHETIC**;合成案例移出该面板(进独立「算法示意」模块或下线);红线:`dataProvenance ≠ VERIFIED` 永不进任何聚合/未来校准样本。
3. **Q3 · 形式约束(并入 Phase 1 PR 或紧随)** —— 区间融入档位卡、不可独立分享;`basisLabel` 结构化非承诺声明字段;冲刺/匹配卡强制「保底校数量」提示。
4. **Q5 · 引擎分层(1 PR)** —— 现有系数标 `v-frozen` + 审计日志;明确划出「分类逻辑层」;新增「选校结构诊断层」(冲稳保分布失衡检测);排查并按 bug 修复事实性错误(如国际生 need-aid)。
5. **Q2 · 核查(≈0 工程)** —— 确认 `PredictionResult` 落库 serve-time 的 tier/区间/引擎版本且不被覆盖。

**明确推迟(不在本批,gated on 真实上线 + 真实用户):**

- 结果上报问卷 UI(首批用户放榜期前 1 个月再做)。
- Platt scaling 校准层(攒到 ~200-500 条真实结果后)。
- `AdmissionCase` 入库管线重写(补结构化字段)。

## 一句话

预测数字永远只锚定**官方聚合数据 + 冻结的规则引擎**;个别案例只做**带 provenance 隔离的展示**、永不进数字;「精准」在拿到真实录取结果前的唯一诚实形态是**区间形状诚实 + 档位为裁决 + 选校结构诊断**;真正可验证的「准」要等结果飞轮,而那一天到来前不做任何 calibration theater。
