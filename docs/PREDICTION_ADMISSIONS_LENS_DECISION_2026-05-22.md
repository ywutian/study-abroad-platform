# 招生官评估视角方案 —— 辩论决策记录

> 2026-05-22 · 6-lens architecture debate(学生家长 / 留学顾问 / 创始人 / 统计严谨 / 红队 / 产品务实)
> 修订并收口 [PREDICTION_ADMISSIONS_LENS.md](./PREDICTION_ADMISSIONS_LENS.md) 设计稿。
> 一句话结论:**方案对,但被砍小了** —— 不要 `buildAdmissionsLens` service,不要 5 级评级词;它实际是 Phase 1 之上一个 ~1.5 天的便宜切片。

## Contested questions

1. 四轴拆解 vs 单一裁决 —— 对中国高三学生/家长,4 轴读数是更有参考价值,还是信息过载?
2. 个人轴「诚实留白」—— 明说「这项我们看不到、且它权重最高」,是建立信任还是摧毁信任?
3. 课外轴「rubric 与招生官同源」论证成立吗?
4. 每轴「词级评级」由读 modifier 乘数派生 —— 是真增量,还是把不可验证的数字换成不可验证的词?
5. pre-launch / 51 用户阶段,现在投入做四轴 lens 对不对,还是先上 Phase 1?

## Unanimous / 一致点 — adopt directly

- **Q2 → 个人轴诚实留白,保留、立刻做。** Why:如实暴露不确定性的最大来源,是统计诚实的教科书做法;且实现成本最低(一条静态 i18n 串)。中国家长被「保证录取」中介坑多了,「我们看不到文书」反而是信任锚。
- **Q3 →「rubric 同源」论证永不进用户文案。** Why:招生官的 rubric 被年度真实录取结果隐式校准过,平台 rubric 从没见过一条结果 —— 两者都叫 rubric 不代表认知地位相同。该论证只能留在工程文档里作为「为什么允许显示」的内部依据;课外轴对外必须自称「课外申报强度(结构化部分)· 初步估算,不代表招生官实际判断」。**不新建 rubric 打分引擎。**
- **Q1 → 做四轴「分组呈现」,但不是新 service。** Why:给引擎已有的 `factors[]` 每条打一个 `axis` tag + 前端 `groupBy` 成四组,即可得到中国家长要的「四桶报告」观感。创始人主动撤回 `buildAdmissionsLens`:「家长永远看不见后端是 tag 还是嵌套对象」。

## Majority / 多数点 — adopt with noted dissent

- **Q5 → Phase 1 区间 + 四轴便宜切片,合并成一个 PR 一次上(~1.5 天)。** Why:四轴「分组」不依赖真实录取数据(依赖 CDS,已有),也不是新工程 —— 它就是 Phase 1 的一个增量。分两次发布只会拖慢 launch。
  Dissent(红队):四轴一上线就是 4 个可被逆向、可被当承诺、可被截图维权的断言面,Phase 1 只有 1 个;0 真实结果时主动扩成 4 个 = 在无校准数据时放大声誉敞口。红队主张四轴切片由「≥30 条真实录取结果回流」触发。**记录在案** —— 若上线后出现因某一轴引发的纠纷,此条应被重新打开。

## Conflicts → resolution / 分歧 → 裁决

### Q4 — 词级评级:5 级词 vs 引擎已有的 3 态?

- Positions:设计稿原案 = 5 级词(突出/有竞争力/达标/临界/偏弱)由 modifier 乘数派生。统计严谨 + 产品务实:引擎里**本来只有 3 态 `impact`(positive/neutral/negative)**,5 级词是把未校准乘数从 3 态**上采样**到 5 级 —— 凭空多造 2 个引擎从没算过的刻度,是「比点概率更阴险」的伪精确(连可疑性都藏了)。
- **Resolution:杀掉 5 级词。** 用引擎已有的 3 态,人话 relabel 为 **顺风 / 中性 / 逆风**,每个 tag 必须绑它的可见依据 factor。赢在:呈现刻度必须 = 引擎实际信息量,引擎只知道「帮忙/无所谓/拖累」3 件事,就只说 3 件事。留学顾问与创始人均从「接受词级」**移动**到此(创始人:「我当初接受词级是工程直觉失误,不是商业判断 —— 专业感由四桶卡片给,不由词的档数给」)。
- Counter-argument considered:「5 级词比点概率温和、不假装精准」—— 否决,5 级渐变**本身就是**精准声明(宣称平台能分辨 5 层),引擎做不到。

### Q1-补 — 每轴该不该带「下一步该做什么」?(留学顾问 vs 红队)

- Positions:顾问要「诊断式 —— 每轴带下一步」(否则退化成体检报告);红队要「轴评级只读,绝不给提升钩子」(否则 = 教中国学生挂名水奖堆头衔 game 招生)。
- **Resolution:轴评级只读、轴上不挂 todo 按钮;「下一步」收口为一个全局的、方向性的「与顾问对话」出口。** 二者在 Stage 3 都移动到一条共同边界 —— 一条「下一步」合法 iff 指向**不可速成的真实建设/策略调整**(「把文书找懂的人看」「重新平衡冲稳保」),非法 iff 指向**可速成的简历动作**(「再加两个社团」「拉 GPA」)。红队的判定法则:**「学生照做后,招生官会更准还是更难看到 ta 真实是谁?」** 更准→放行,更难→禁止。
- 额外裁决(红队,采纳):**课外轴本身绝不输出 actionable item** —— 它的天然「解法」就是简历注水;课外轴唯一允许的「下一步」是转嫁给个人/文书轴(「这段活动的价值取决于你怎么在文书里讲」)。

## Sharpened points / 锐化的点

1. **四轴必须「非同构」呈现(统计严谨的核心贡献)。** 设计稿默认四轴长一样。辩论锐化为:**呈现形态必须随认知地位分化** —— 学术轴有真实 CDS 百分位(真测量)→ 显示百分位数字;课外轴/契合轴只有引擎 3 态 → 显示 顺风/中性/逆风 词;个人轴无信号 → 留白。每轴挂一个认知地位徽章(`校方数据` / `平台启发式评估·未经录取结果校准` / `不可见`)。四轴视觉对称会骗用户以为「contextual fit 的顺风」和「GPA 第 68 百分位」是同一种东西。
2. **个人轴留白必须带「出口」且与档位误差物理隔离。** 设计稿原案是一段免责式留白。锐化为:(a) 留白后必须跟一句家长今晚能做的真实动作(「把文书拿给懂申请的人看」)—— 没有出口的留白是甩锅,有出口的留白才是诚实;(b) 留白的措辞必须物理隔离,只说「个人轴这一项我们不评」,**绝不能**让用户把它读成「整体档位预测出错也不怪我们」—— 档位是 CDS 驱动的硬预测,其误差责任不能被个人轴留白稀释。
3. **方案从「service + 5 级词 + i18n 大工程」锐化为「一个 PR 的便宜切片」。** 设计稿落地清单是 `buildAdmissionsLens` 后端服务 + 预测卡重组 + 评级词派生 + 大批 i18n。辩论锐化为:`factors[].axis` 标注 + 前端 groupBy + 静态徽章 + 静态留白串 + 每轴一句**静态、profile 无关**的方向句。动态 per-axis 建议是新工程,defer。

## Minority report / 少数派记录

**红队(Q5)**:即便切到 1.5 天,四轴上线仍把平台的「可被维权的断言面」从 1 个扩到 4 个。便宜的是代码,贵的是「4 个面同时错时的信任崩塌」。在 0 条真实录取结果、任何一轴都无法被校准或证伪时上线四轴,是在无数据时主动放大声誉敞口。红队主张:四轴切片应由「≥30 条真实录取结果回流」触发,在那之前只上 Phase 1。**这是本记录日后最该回看的一行** —— 若上线后任一轴引发家长纠纷/舆情,按此条重开决策。

## Build sequence

**合并为一个 PR(在 `feat/prediction-honest-interval` 分支上,与已实现的 Phase 1 同发):**

0. **先验证事实(shipping 的待查项)** — grep `prediction` 模块:引擎 `factors[]` 的粒度。`activityStrengthComponent`/`awardStrengthComponent` 已存在并喂 `profileContextMultiplier` —— 但若 `profileContext` 只 emit **一个合并 factor**,课外轴无法干净拆出。若是合并的:要么让 profileContext emit 子-factor、要么课外轴本批并入「契合」或标 `coming soon`。**这个事实决定课外轴进不进本批。**
1. **`factors[].axis` 标注** — 后端给每个 factor 打 `axis: 'academic' | 'extracurricular' | 'personal' | 'fit'`。纯数据标注,非新计算。
2. **前端 groupBy** — 预测卡展开区按 axis 分四组;渐进披露:档位仍是头条,四轴默认折叠成 4 个一行标签(**验收红线:一眼扫完,拒绝 4 段散文**)。
3. **非同构呈现** — 学术轴渲染 CDS 百分位数字(复用 `calculateGpaPercentileFromCds` + 新增标化正态拟合);其余轴渲染 3 态(顺风/中性/逆风);每组挂静态认知地位徽章。
4. **个人轴留白** — 静态 i18n 串 + actionable 出口(**验收红线**);措辞与档位误差物理隔离。
5. **3 态 relabel** — 引擎 3 态 `impact` → 顺风/中性/逆风,绑可见依据 factor。**不引入 5 级词。**
6. **课外轴文案** — 自称「课外申报强度(结构化部分)· 初步估算」;无 actionable hook。
7. **全局出口** — 一个方向性「与顾问对话」入口(承接顾问的「指方向」+ 创始人的转化钩子)。

**明确不做**:`buildAdmissionsLens` service · 5 级评级词 · 新 rubric 打分引擎 · 动态 per-axis 建议 · 「rubric 同源」用户文案 · 逐轴 todo 按钮。

**明确推迟(gated)**:动态个性化 per-axis 建议;四轴评级的实证校准 —— 由「≥30 条真实录取结果回流」触发(红队少数派意见的硬门槛)。

## 一句话

> 招生官评估视角方案**成立**,但辩论把它从一个大工程砍成了 Phase 1 之上的一个 ~1.5 天便宜切片:给已有 `factors[]` 打 axis tag + 前端分四组 + 非同构呈现(学术轴真百分位 / 课外契合轴 3 态词 / 个人轴诚实留白)。杀掉 5 级评级词(伪精确)、`buildAdmissionsLens` service(用户看不见)、「rubric 同源」话术(认知地位不对等)。和 Phase 1 区间合并成一个 PR 一次上。
