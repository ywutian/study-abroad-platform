# Platform Data Field Matrix

> Campaign 1 output for `PLATFORM_DATA_INTELLIGENCE_EXECUTION_PLAN.md`.
> Purpose: convert the platform-data goal into a concrete operating map.

## Legend

- Priority: P0 blocks trust or core application decisions; P1 improves decision quality; P2 improves engagement or operations; P3 is internal optimization.
- Freshness: cycle data should be refreshed per application year; annual data should be refreshed every 12 months; event data should refresh before each event season; runtime data is continuously updated.
- Quality: every sourced fact should carry provenance, source URL, cycle/effective year, confidence, review status, and terminal/conflict status where applicable.

## Cross-Domain Gaps Found In This Pass

| Gap                                                                       | Evidence                                                                                                                            | Why It Matters                                                              | Suggested Campaign                                                                                             |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Notification persistence needed an explicit contract                      | Notification docs previously implied `Notification` and `PushToken` models, but implementation stores feed and tokens in Redis only | Deadline reminders and review notices are user-trust data, not just cache   | Resolved by ADR-0021: Redis is an ephemeral delivery cache; P0/P1 data closure remains in owning domain models |
| Target school source is duplicated                                        | `ProfileTargetSchool` still exists while `SchoolListItem` is canonical                                                              | Prediction/profile analysis can read the wrong source if legacy paths drift | Keep proxy behavior documented; audit all readers and deprecate writes to `ProfileTargetSchool`                |
| Documentation names drift from schema                                     | Architecture references `EssayExample` and `TimelineTask`; schema uses `AdmissionCase` essay fields and `ApplicationTask`           | Data map and generated docs can mislead operators                           | Reconcile docs and add a schema-doc consistency check                                                          |
| Essay/deadline quality gates are weaker than prediction gates             | Prediction has coverage/closure tooling; essays and deadlines are more scattered                                                    | These are yearly-changing application execution facts                       | Create essay/deadline coverage + freshness reports with source-quality gates                                   |
| Applicant completeness is not yet a data campaign                         | Existing docs identify missing GPA, round, nationality, activity/award links as high leverage                                       | Better school data cannot compensate for sparse user profile context        | Add applicant-completeness coverage and targeted gap prompts                                                   |

## Field-Level Source Rules To Encode Next

- Prediction anchors must prefer full-applicant-pool data and avoid platform-user calibration.
- Essay prompts and deadlines must prefer official admissions or Common App style sources; secondary blog sources require review and visible provenance.
- User-generated cases must never become prediction training data without explicit future ADR change; they remain diagnostic and community evidence.
- Media assets need automated lexical/pixel suspicion filters plus human approval for primary cards.
- Notifications use the ADR-0021 ephemeral delivery-cache contract and readiness delivery policy; P0/P1 closure must remain in owning domain models.
- AI memory and graph data must preserve user consent, source category, expiry, and sensitivity tier.
