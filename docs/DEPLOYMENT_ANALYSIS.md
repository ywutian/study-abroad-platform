# 留学申请平台 — 部署与基础设施全面分析

> 结合产品技术栈与所有候选部署方案的一体化分析，便于选型与后续迁移。  
> 最后更新：2026-02

---

## 一、产品与技术栈总览

### 1.1 应用构成

| 应用       | 技术                                 | 说明                                                |
| ---------- | ------------------------------------ | --------------------------------------------------- |
| **web**    | Next.js (App Router)、next-intl、PWA | 主站前端，SSR/ISR，多语言，支持 Cloudflare 构建脚本 |
| **api**    | NestJS、Prisma、Socket.IO            | 单体 API，含 WebSocket（Chat、AI Agent）            |
| **mobile** | Expo (React Native)                  | 移动端，与 API 同源                                 |

### 1.2 后端依赖（按必选/可选）

| 依赖           | 必选     | 用途                                                                  | 备注                   |
| -------------- | -------- | --------------------------------------------------------------------- | ---------------------- |
| **PostgreSQL** | ✅       | 主库，60+ 模型（用户、档案、学校、案例、论坛、聊天、支付、AI 记忆等） | 含 pgvector（AI 向量） |
| **Redis**      | 可选     | 登录暴力破解、限流、AI 队列/缓存；不配则内存降级                      | 多实例时建议配         |
| **SMTP**       | 可选     | 验证邮件、通知、支持邮箱                                              | 不配可 mock            |
| **OpenAI**     | 可选     | AI 助手、文书相关、内容审核等                                         | 不配则相关功能不可用   |
| **对象存储**   | 可选     | 本地 / S3 / OSS / COS，验证材料、附件等                               | 默认 local             |
| **Webhook**    | 生产建议 | 支付回调等                                                            | 需公网可达 API         |

### 1.3 部署相关特性

- **API**：Docker 化（Node 20 Alpine），需长连（WebSocket）、可能长耗时（AI、部分请求）。
- **前端**：已有 `build:cloudflare` / `deploy`（OpenNext + Cloudflare），也可纯 Vercel。
- **本地编排**：docker-compose 含 db（pgvector）、redis、api、web、nginx（production profile）。

## 二、基础设施需求矩阵

| 能力       | 需求                              | 说明                                      |
| ---------- | --------------------------------- | ----------------------------------------- |
| 持久化 DB  | PostgreSQL 15+，建议支持 pgvector | 迁移/备份策略要提前想好                   |
| 长连接     | WebSocket（Chat、AI Agent）       | 需支持 WS 或兼容方案（如 sticky session） |
| 长请求     | 部分 AI/预测接口 30s–2min         | 需可配置请求超时                          |
| 定时任务   | 内置 @nestjs/schedule             | 单实例或专用 worker 均可                  |
| 多区域     | 海外为主                          | 选 region 时优先北美/欧洲                 |
| 合规与安全 | 支付、个人信息                    | 备份、审计、HTTPS、密钥管理               |

## 三、当前部署形态（你正在用的）

- **前端**：Vercel
- **API**：Railway
- **数据库**：Neon

特点：上手快、成本可控；Neon 与 Railway 可能有冷启动/连接回收，易触发登录或刷新超时（你已通过 Redis 超时与 auth 超时做了缓解）。

## 四、所有部署产品按层级对照

### 4.1 前端托管

| 产品                      | 免费/永久免费        | 付费档     | 与当前产品匹配度                              | 备注                   |
| ------------------------- | -------------------- | ---------- | --------------------------------------------- | ---------------------- |
| **Vercel**                | Hobby 免费（有限额） | Pro $20/月 | ⭐⭐⭐⭐⭐ Next 官方生态，SSR/ISR 完整        | 商用建议 Pro           |

## 五、按目标的推荐组合

### 5.1 目标：一步到位、少迁移（海外、正式上线）

| 层级   | 推荐                       | 备选                         |
| ------ | -------------------------- | ---------------------------- |
| 前端   | Vercel Pro                 | -                            |
| API    | GCP Cloud Run              | AWS App Runner / ECS Fargate |
| 数据库 | GCP Cloud SQL (PostgreSQL) | Neon Pro / RDS               |
| Redis  | GCP Memorystore            | Upstash                      |
| 存储   | GCP Cloud Storage 或 R2    | S3                           |
| 邮件   | Resend / SendGrid 免费额度 | 自建 SMTP                    |

**特点**：后端集中在一家云，账单与运维统一；Cloud Run 自动扩缩，适合从 0 到成长期。

---

### 5.2 目标：尽量永久免费（个人/MVP）

| 层级   | 推荐                           | 说明                    |
| ------ | ------------------------------ | ----------------------- |
| 前端   | Vercel Hobby                   | 在条款与限额内长期免费  |
| API    | GCP Cloud Run                  | 用满免费额度内可长期 $0 |
| 数据库 | Neon 免费档 或 Supabase 免费档 | 0.5GB/500MB 级          |
| Redis  | 不配 或 Upstash 免费档         | 不配则接受降级          |
| 存储   | local 或 GCP 5GB / R2 10GB     | 在免费额度内            |
| 邮件   | 不配 或 免费额度 SMTP          | 不配则 mock             |

**边界**：数据量与请求量要在各产品免费限额内；OpenAI 不配则 AI 功能不可用。

---

### 5.3 目标：成本优先（VPS 自管）

| 层级        | 推荐                         | 说明                             |
| ----------- | ---------------------------- | -------------------------------- |
| 前端        | Vercel（免费或 Pro）         | 仍建议托管，省心                 |
| API + Redis | 单台 VPS (4GB) Docker        | NestJS + Redis 同机或 Redis 小机 |
| 数据库      | 同机 PostgreSQL 或 Neon 免费 | 同机要自己做备份与升级           |
| 存储        | 本地或 R2/S3 免费档          | 视用量选                         |

**特点**：月费约 $20–50，需要一定运维能力。

---

### 5.4 目标：当前栈 + Cloudflare 增强（少改动）

| 层级      | 推荐                      | 说明                        |
| --------- | ------------------------- | --------------------------- |
| DNS + CDN | Cloudflare                | 域名解析、代理、缓存、防护  |
| 前端      | 保持 Vercel               | 或试 Pages（已有 OpenNext） |
| API       | 保持 Railway              | 或迁 Cloud Run              |
| 数据库    | 保持 Neon                 | -                           |
| Redis     | Railway add-on 或 Upstash | -                           |
| 存储      | 可选 Cloudflare R2        | S3 兼容，免费 10GB          |

**特点**：不动大架构，先加一层 Cloudflare，必要时再把 API/DB 迁到一家云。

## 七、迁移与风险简表

| 从 → 到             | 难度 | 主要动作                                  | 风险点                   |
| ------------------- | ---- | ----------------------------------------- | ------------------------ |
| Railway → Cloud Run | 中   | 镜像/构建、环境变量、VPC/Redis 连通       | WebSocket、冷启动、超时  |
| Neon → Cloud SQL    | 中   | 导出/导入、连接串、可能调 pool            | 停机窗口、pgvector 扩展  |
| 当前 → 全 GCP       | 中高 | 上述 + 存储/邮件/监控                     | 一次性配置多             |
| 当前 → VPS          | 中   | 一台机 Docker Compose，域名指过去         | 备份、安全、高可用自管   |
| 加 Cloudflare       | 低   | DNS 切到 CF，API 源站指 Railway/Cloud Run | 缓存规则、WebSocket 穿透 |

## 八、建议的下一步（结合你产品）

1. **短期**：保持 Vercel + Railway + Neon，已做的 auth/Redis 超时与文档继续用；若希望更稳，加 Cloudflare DNS + 代理。
2. **正式上线 / 一步到位**：规划迁到 **Vercel + GCP**（Cloud Run + Cloud SQL + Memorystore），按本文第五节做环境与迁移清单。
3. **预算紧**：在「永久免费」或「VPS」里选一条，控制 DB/API 规模在免费或单机可承受范围内。
4. **文档与运维**：把本分析里的选定方案写成 `docs/RUNBOOK.md` 或 `docs/DEPLOYMENT.md`，记录实际使用的域名、环境变量、备份与告警策略。
