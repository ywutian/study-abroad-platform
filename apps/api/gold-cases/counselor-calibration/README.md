# Counselor Calibration Spec — Layer 3 fixtures

Industry-anchored test cases for the `CounselorEngineService` (prod served prediction engine). See [`docs/PREDICTION_CALIBRATION_METHODOLOGY.md`](../../../../docs/PREDICTION_CALIBRATION_METHODOLOGY.md) for the full methodology.

## Layout

```
counselor-calibration/
├── schema.ts              ─ TypeScript types for fixture JSON
├── cases/                 ─ one JSON file per fixture (standalone or comparative)
├── reports/               ─ generated by `pnpm calibration:counselor`
└── README.md              ─ this file
```

## How to run

```bash
cd apps/api
pnpm calibration:counselor          # runs all fixtures + writes markdown report
pnpm calibration:counselor --json   # also emits JSON report
```

Exit code:

- 0 — all fixtures pass
- 1 — at least one fixture failed (CI-gating)

## How to add a fixture

1. Pick a scenario group from the 18 in `schema.ts:ScenarioGroup` (or add a new one — document it in the methodology doc § 3.3)
2. Create `cases/NNN-school-archetype-tag.json` following the schema (see existing fixtures for examples)
3. **Required**: `rationale.sources[]` with ≥ 1 public citation (NACAC report / Crimson aggregate / CDS / school admissions blog)
4. Run locally `pnpm calibration:counselor` → if pass, ship; if fail, decide:
   - Engine has a bug → fix engine, fixture stays
   - Fixture expectation is wrong → update with new citation
   - Engine and intuition both reasonable but disagree → document the disagreement in PR, hold

## When to update existing fixtures

| Trigger                                               | Action                                                                                                                                                                                                                        |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NACAC / Crimson / IvyWise annual report               | Re-check each fixture's `expectedProbabilityRange`; update `lastReviewedAt`                                                                                                                                                   |
| School publishes new CDS                              | Only matters if anchor data changes; expectation usually unchanged                                                                                                                                                            |
| Verified outcome data accumulates (post-Decision-Day) | Cross-check the spec against real outcome rates; large divergence is a calibration discussion                                                                                                                                 |
| Engine refactor                                       | DO NOT update the spec to match new engine output — that defeats the point. Run the spec against the new engine; failures point to either engine bug or genuine improvement (in which case bump engine version and add notes) |
